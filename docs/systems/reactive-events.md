# 리액티브 알림과 고정 이벤트

> 근거: bible 5.6(4종 트리거), 5.4(고정 이벤트), 5.5(이동 중 문자), 7장 각 세션.

## 1. 트리거 4종

| 종류 | 발화 조건 | 예 |
|---|---|---|
| 도착(arrive) | 장소 도착 | 장소 NPC 대화 개시 |
| 획득(acquire) | 특정 K/플래그 획득 후 N초(실시간) | K-10 → 30초 후 유진 문자 |
| 유휴(idle) | 진행 없음 N초 | `systems/idle-nudge.md` |
| 고정(fixed) | 게임 시각 + 장소 조건 | 16:10 민재 |

## 2. 큐 규칙

- 예약된 이벤트는 `queue`에 `{id, fireAt(실시간ms 또는 게임시각), cond, priority}`로 들어간다.
- 발화 시점에 `cond`를 **다시 평가**한다(예약 후 상황이 바뀌었으면 취소).
- 동시에 여러 이벤트가 발화하면 priority 높은 것부터 **최소 4초 간격**으로 흘린다(배너 겹침 방지).
- 대면(face) 대화 중에는 문자/톡 이벤트가 배너 없이 진동음만 내고 쌓인다. 대화가 끝나면 배너.
- 통화 중 착신 이벤트는 대기. 통화 종료 후 2초 뒤.
- 같은 id는 한 번만 발화(`once: true` 기본).
- 이동 중(travel)에는 문자 이벤트 발화 허용(5.5 "긴장 유지"). 이동 애니메이션 위로 배너.

## 4. 이벤트 정의 필드

`data/schema-event.md` 참조. 요약: `id, kind(fixed|acquire|idle|arrive), trigger, cond, delay{realMs, gameMin}, actions[], priority, once, cancelIf`.

## 5. 설계 금지 사항

- 리액티브 알림으로 K를 "설명"하지 않는다. NPC는 자기가 아는 것만 보낸다(유진의 RE.01·RE.02는 감시자라서 아는 것).
- 같은 NPC의 리액티브가 3분(실시간) 안에 2회 이상 오지 않게 한다(스팸감 → 몰입 저하). 단 지훈의 연발 버블은 1회로 친다.
- 엔딩 판정에 영향을 주는 정보는 리액티브로만 얻게 하지 않는다(놓칠 수 있으므로). 리액티브는 보조 채널.
