# 기술 아키텍처

> 근거: CLAUDE.md(웹앱, PC + iPhone, Xcode 없음), bible 5장·12장. **이 문서는 구현 방침만 정한다. 코드는 아직 쓰지 않는다.**

## 1. 스택 결정

| 영역 | 결정 | 이유 |
|---|---|---|
| 언어 | TypeScript | 데이터 ID·조건식·상태 타입을 컴파일 타임에 잡는다. K/F ID 오타가 곧 진행 불가 버그다 |
| 빌드 | Vite | 설정 최소, PC에서 개발 → iPhone에서 LAN 접속 테스트(`--host`) |
| UI | React 18 | 폰 UI = 화면 스택 + 오버레이. 컴포넌트 재사용(버블, 리스트, 배지)이 많다 |
| 상태 | 단일 스토어 + 액션 로그(이벤트 소싱). 라이브러리는 Zustand 또는 순수 reducer | 세이브·재현·디버그가 전부 액션 로그에서 나온다(아래 4장) |
| 스타일 | CSS Modules + CSS 변수(두 폰 테마 전환) | 아버지 폰(라이트·큰 글씨) ↔ 옛 폰(다크·작은 글씨)을 변수 세트 교체로 |
| 데이터 | JSON(콘텐츠) + 빌드 타임 검증 스크립트 | `data/README.md` |
| 오디오 | Web Audio API(효과음·진동음·환경음 루프) + `<audio>`(긴 음성) | iOS 첫 탭 언락 필요 → `systems/audio-and-haptics.md` |
| 저장 | localStorage(세이브 슬롯) + IndexedDB(액션 로그, 선택) | 서버 없음 |
| 배포 | 정적 호스팅(GitHub Pages 또는 Vercel) + PWA(manifest, service worker) | 홈 화면 추가 시 주소창 없는 전체 화면 → "폰 속의 폰" 몰입 |
| 테스트 | Vitest(엔진 단위), Playwright(경로 시나리오 자동 플레이) | `qa/test-scenarios.md`의 TS를 자동화 |

> 대안 검토: 순수 바닐라 JS는 화면 수(앱 9개 × 하위 화면)에 비해 유지보수가 무겁다. 게임 엔진(Phaser 등)은 텍스트·리스트 UI가 대부분인 이 게임에 과하다. → React로 확정.

## 2. 모듈 구성

```
src/
  engine/          ← UI와 무관한 순수 로직 (테스트 대상 1순위)
    state/         상태 타입, 초기 상태, 리듀서
    actions/       액션 정의(모든 상태 변경의 유일한 입구)
    conditions/    조건식 파서·평가기
    effects/       효과(K 획득, 플래그, 시간 진행, 이벤트 예약) 적용기
    scheduler/     리액티브 큐, 고정 이벤트, 유휴 타이머
    progression/   세션 그래프, 진입/종료 판정, 허브 단계
    dialogue/      대화 트리 러너
    endings/       엔딩 판정기
    save/          직렬화, 마이그레이션
  content/         ← 데이터 로더 + 타입(JSON → 검증된 객체)
  ui/
    device/        폰 프레임, 상태바, 잠금화면, 홈, 오버레이 레이어
    apps/father/   phone, messages, talk, contacts, photos, nav, bank, memo, settings, camera
    apps/old/      lock, home, messages, memo, voice, photos, calculator
    scenes/        장면 뷰, 인터폰, CCTV 스크러버, 이동 화면, 엔딩 시퀀스
    meta/          타이틀, 설정, 크레딧, 디버그 패널
  audio/
  data/            ← 빌드 시 복사되는 콘텐츠 JSON
tools/
  validate-content  ← ID 참조 무결성, 조건식 문법, 매트릭스 경고
```

규칙: `engine/`은 React·DOM·오디오를 import하지 않는다. UI는 엔진 상태를 구독하고 액션만 dispatch한다.

## 3. 런타임 루프

1. 플레이어 입력(탭) → UI가 `Action` dispatch.
2. 리듀서가 상태 갱신 → 효과 적용기가 연쇄 효과 처리(K 획득 → 리액티브 예약 등).
3. 스케줄러가 `게임 시계`와 `실시간 타이머`(유휴 넛지, 리액티브 지연 초) 두 축을 관리.
4. 진행 판정기가 세션 종료/진입 조건을 매 액션 후 평가.
5. UI는 상태 변화에 따라 알림 배너·화면 전환을 렌더.

두 개의 시간 축을 혼동하지 않는다:
- **게임 시계**(`state.clock`): 상태바에 보이는 시각. 이벤트·이동으로만 흐름.
- **실시간**(ms): 리액티브 지연("30초 후"), 유휴 넛지(90/180/300초), 연출 대기(3~5초 이동 애니메이션). 앱이 백그라운드로 가면 실시간 타이머는 일시정지.

## 4. 액션 로그(이벤트 소싱)

- 모든 상태 변경은 `{t: 실시간ms, type, payload}` 액션으로 기록.
- 세이브 = 최신 스냅샷 + 스냅샷 이후 액션 로그.
- 장점: (1) 버그 리포트에 로그만 첨부하면 그대로 재현, (2) 플레이테스트 텔레메트리(세션별 체류 시간, 막힌 지점)가 로그에서 바로 계산, (3) Playwright 경로 테스트가 로그 재생으로 대체 가능.
- 비결정성 금지: 엔진 안에서 `Math.random`, `Date.now` 직접 호출 금지. 필요한 값은 액션 payload로 주입.

## 5. 화면 계층 (z-order)

| 레이어 | 내용 |
|---|---|
| 0 | 장면(일러스트) 또는 폰 배경 |
| 1 | 폰 프레임 내부: 잠금화면 / 홈 / 앱 화면 스택 |
| 2 | 상태바(항상 표시) |
| 3 | 알림 배너(문자·톡·부재중), 독백 알림 |
| 4 | 시스템 다이얼로그(F-03 확인 등) |
| 5 | 풀스크린 연출(시간 점프, 기기 전환, 엔딩) |
| 6 | 디버그 패널(개발 빌드만) |

## 6. 반응형·기기 대응

- 기준 뷰포트 390×844(iPhone 14/15). 최소 360×640.
- 모바일: 화면 전체가 "아버지 폰"이다(폰 프레임 미표시). 데스크톱: 가운데 폰 프레임(9:19.5) + 바깥은 어두운 배경.
- `100dvh`, `env(safe-area-inset-*)` 사용. iOS 주소창 변화로 레이아웃이 튀지 않게.
- 가로 모드: "세로로 돌려주세요" 오버레이(게임 정지).
- 핀치 줌·더블탭 줌 비활성화(`touch-action`, viewport meta). 텍스트 크기는 게임 내 설정으로만.

## 7. 개발용 도구 (디버그 패널)

- K/F/v 토글, 세션 점프, 시계 설정, 리액티브 큐 보기·즉시 발화, 유휴 타이머 배속(×10), 액션 로그 내보내기/불러오기, 엔딩 판정 미리보기.
- URL 파라미터 `?debug=1`로만 노출. 프로덕션 빌드에서 제거.
