# PRODUCT PRINCIPLES — DONTKNOW

> **역할:** 모든 설계·콘텐츠·구현 결정의 판정 기준. "이 기능이 들어갈 수 있는가"는 이 문서의 기둥과 가이드라인으로 답한다.
> **단일 출처:** 디자인 기둥 P1~P7과 콘텐츠 가이드라인은 이 문서다. 원문은 [[PRODUCT_PRINCIPLES](PRODUCT_PRINCIPLES.md)](PRODUCT_PRINCIPLES.md) 3·7절.
> **참조:** [`Bible.md`](Bible.md), [`PRODUCT_VISION.md`](PRODUCT_VISION.md), [`../01-product/NARRATIVE_CANON.md`](../01-product/NARRATIVE_CANON.md), [`../01-product/CHARACTERS.md`](../01-product/CHARACTERS.md).

## 1. 디자인 기둥 P1~P7

> 이 문서의 표를 그대로 옮긴다. 각 기둥은 위반 예시가 하나라도 있으면 그 기능을 넣지 않는다.

| 기둥 | 뜻 | 위반 예시(금지) |
|---|---|---|
| **P1. 폰이 곧 수사 도구다** | 모든 핵심 정보는 실제 폰 기능(메타데이터·동기화·계정·설정·알림)을 조작해서 얻는다 | NPC가 정답을 말해 준다. 컷신이 정보를 준다 |
| **P2. 추리는 머릿속, 증명은 손끝** | 게임은 단서를 잇거나 판정하지 않는다. 플레이어가 알아낸 것을 **폰에서 행동으로** 쓸 때만 세계가 반응한다([`ACTION_PROOF`](../01-product/ACTION_PROOF.md)) | 카드·"연결 성공" 같은 판정 UI. "새 단서 발견!" 알림 |
| **P3. 보는 것도 흔적이다** | 읽음 표시, 스토리 조회, 활동 상태, 동기화된 사진·메모, 로그인 알림. 플레이어의 조사 행위 자체가 아들과 추적자에게 보이고, 그들이 반응한다([`TRACES_AND_REACTIONS`](../01-product/TRACES_AND_REACTIONS.md)) | 플레이어만 움직이는 정적인 증거 보관함 |
| **P4. 모든 진실은 두 길 이상** | 진행·엔딩에 필요한 행동의 근거는 서로 다른 앱 2개 이상에서 얻을 수 있다 | 한 화면을 놓치면 막히는 단일 경로 |
| **P5. 감정은 데이터가 말한다** | 독백으로 감정을 설명하지 않는다. 숫자·시각·지워진 흔적·읽지 않은 "1"이 말한다 | 아버지가 "내 탓이야"라고 운다 |
| **P6. 현실처럼, 하지만 따라 하게는 하지 않는다** | 사기의 흐름(누가·언제·얼마)은 구체적, 수법(대본·세탁·해킹)은 쓰지 않는다. 폰 기능은 실제 스마트폰에 있는 수준만 쓴다 | 실제 계정 탈취 절차, 존재하지 않는 만능 해킹 기능 |
| **P7. SNS가 수사의 중심이다** | 사람과 조직은 SNS 계정의 흔적(이전 이름·조회자·차단·편집 기록·지워진 댓글)으로 찾는다. 필수 행동의 절반 이상이 SNS를 거친다 | SNS를 "글 몇 개 읽는 곳"으로 쓰기 |

### 1.1 기둥별 판정 질문

| 기둥 | 기능을 넣기 전에 묻는다 |
|---|---|
| P1 | 이 정보를 폰의 어떤 기능(목록·정보(i)·설정·알림·동기화)으로 얻는가? 그 기능이 실제 스마트폰에 있는가? |
| P2 | 플레이어가 이 결론을 폰에서 어떤 **행동**(입력·검색·공유·설정·호출)으로 쓸 수 있는가? 게임이 대신 채점하고 있지 않은가? |
| P3 | 이 행동이 누구에게 어떤 흔적으로 보이는가? 흔적을 피할 다른 길이 있는가? |
| P4 | 이 행동의 근거를 다른 앱에서도 얻을 수 있는가? 하나가 원격 삭제되어도 진행이 막히지 않는가? |
| P5 | 이 감정을 대사 대신 어떤 데이터(시각·횟수·삭제·"1")로 보여 줄 수 있는가? |
| P6 | 수법을 구체적으로 설명하고 있지 않은가? 실제 폰에 없는 감시·해킹 기능을 만들고 있지 않은가? |
| P7 | 이 정보가 SNS 계정의 흔적으로 발견되는가? SNS가 단순 열람처로 전락하지 않았는가? |

## 2. 콘텐츠 가이드라인

이 문서을 그대로 따른다. 이 절은 소재 심의와 린터 금칙어의 기준이다.

- **보이스피싱·계좌 대여:** 흐름만. "통장을 빌려주면 하루 30만 원", "돈이 들어오면 지정 계좌로 보낸다" 수준. 사기 대본, 세탁 방식, 수사 회피 요령은 쓰지 않는다. 업무수칙·교육자료 PDF는 제목과 첫 줄만 판독된다.
- **계정·기기 접근:** 가족이 이미 가진 것(기기, 기기에 로그인된 메일, 가족 날짜로 만든 비밀번호)으로만 연다. 해킹·무차별 대입 없음. 설정 앱의 기능은 실제 스마트폰에 있는 수준(Wi-Fi 기록, 스크린 타임, 근처 공유 기록, 텍스트 대치 등)만 쓴다.
- **피해자:** 박하린의 글은 분노와 슬픔의 실제 말투로. 엔딩에서 피해 회복을 외면하지 않는다.
- **폭력:** 위협은 메시지로만. 신체 폭력 묘사 없음.
- **자해·자살:** 다루지 않는다.
- **실존 브랜드:** 앱·회사·은행·통신사는 전부 가상. iOS를 복제하지 않는다([[SYSTEM_SHELL_SPECIFICATION](../03-features/SYSTEM_SHELL_SPECIFICATION.md)](../03-features/SYSTEM_SHELL_SPECIFICATION.md), [[ICONOGRAPHY_AND_IMAGERY](../02-design/ICONOGRAPHY_AND_IMAGERY.md)](../02-design/ICONOGRAPHY_AND_IMAGERY.md)).

### 2.1 금칙어·검사 대상

콘텐츠 린터가 검사할 항목([[SYSTEM_ARCHITECTURE](../04-tech/SYSTEM_ARCHITECTURE.md)](../04-tech/SYSTEM_ARCHITECTURE.md) 5절):

| 검사 | 기준 |
|---|---|
| 소재 수법 | 사기 대본·세탁·계정 탈취·수사 회피의 구체 절차를 설명하는 문장 |
| 앎 매트릭스 | 인물별로 알 수 없는 정보의 키워드가 대사에 등장하는가 |
| 실존 브랜드 | 게임 UI·대사·아이콘에 실제 서비스명이 있는가(레퍼런스 분석 절 제외) |
| 판정 UI | "정답", "연결 성공", "새 단서", "틀렸습니다" 같은 채점 문구가 화면에 나오는가 |
| 얼굴 | 인물 식별을 얼굴·닮은꼴에 의존하는 서술이 있는가 |

## 3. 의사결정 규칙

### 3.1 원본에 있는 규칙

- 충돌하는 설계 문서가 있으면 `design/`의 v6.2 캐논이 이긴다([`../README.md`](../README.md)).
- 이야기 사실·숫자·ID는 단일 출처 문서를 따른다. 이 문서는 그 값을 바꾸지 않는다.
- 기능이 기둥을 위반하면 기능을 버린다. 예외를 만들지 않는다.
- 게임은 플레이어의 추리를 판정하지 않는다(P2). 확인은 세계의 반응으로만 온다.

### 3.2 기둥 충돌 시 우선순위

> **원본에 명시된 우선순위가 없다.** 아래는 확인 사항이며, 총괄이 P0에서 확정한다.

- 후보 안(확정 아님): P2(판정 없음)와 P4(이중 경로)가 충돌하는 경우 — "두 경로 중 하나만 보면 된다"를 택한다(P4는 '둘 다'가 아니라 '둘 중 하나'). 시간을 늘리기 위해 같은 정보를 두 번 읽게 하지 않는다([`../01-product/PLAYTIME_BUDGET.md`](../01-product/PLAYTIME_BUDGET.md) 5절).
- 후보 안(확정 아님): P3(흔적)와 P4(이중 경로)가 충돌하는 경우 — 흔적으로 인한 손실(삭제·도주)에는 반드시 다른 경로를 둔다([`../01-product/TRACES_AND_REACTIONS.md`](../01-product/TRACES_AND_REACTIONS.md) 6절).
- 후보 안(확정 아님): P5(감정은 데이터)와 P1(폰 기능)이 충돌하는 경우 — 감정 설명을 위한 독백·컷신을 추가하지 않고, 데이터를 더 정확히 보여 주는 쪽을 택한다.

## 확인 사항

- **Q-OPEN-03:** 이 문서에 P1~P7의 충돌 시 우선순위가 없다. 3.2의 후보 안은 확정이 아니다. P0에서 서현이 결정해야 한다.
- **Q-OPEN-04:** 콘텐츠 린터의 금칙어 목록(소재 수법·앎 매트릭스 키워드·실존 브랜드)의 실제 단어 목록은 원본에 없다. 콘텐츠 작성 시 [[SYSTEM_ARCHITECTURE](../04-tech/SYSTEM_ARCHITECTURE.md)](../04-tech/SYSTEM_ARCHITECTURE.md) 5절을 구현하며 확정한다.
