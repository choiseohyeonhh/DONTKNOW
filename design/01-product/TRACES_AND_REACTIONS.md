# 흔적과 반응 — 리액티브 시스템

## 문서 정보

| 항목 | 내용 |
|---|---|
| 역할 | 플레이어의 조사 행위가 상대에게 남는 흔적과, 그 흔적에 대한 NPC 반응의 지연·회피 규칙을 정의한다. |
| 단일 출처 범위 | 흔적 ID `TR-01`~`TR-19`, 흔적 표, 도현의 시야, 반응 지연 시간, 흔적을 일부러 남기는 전략, 설계 규칙. |
| 참조 문서 | 사건 `EV-xx`·NPC 상태 [PROGRESSION_AND_ENDINGS.md](PROGRESSION_AND_ENDINGS.md) · 행동 증명 `V-xx` [ACTION_PROOF.md](ACTION_PROOF.md) · 앎 매트릭스 [CHARACTERS.md](CHARACTERS.md) · 설정 메뉴 [SETTINGS_SPECIFICATION.md](../03-features/SETTINGS_SPECIFICATION.md) · 데이터 린터 [DATABASE_SCHEMA.md](../04-tech/DATABASE_SCHEMA.md) · P4 [PRODUCT_PRINCIPLES.md](../00-foundation/PRODUCT_PRINCIPLES.md) · 단서·보존 수단 [EVIDENCE_LEDGER.md](EVIDENCE_LEDGER.md) |

> 이 게임의 "살아 있는 폰"은 여기서 나온다. 플레이어의 조사는 조용하지 않다. **보는 것, 여는 것, 찍는 것, 켜고 끄는 것이 상대에게 흔적으로 간다.** 상대는 흔적에 반응하고, 그 반응이 새 정보이자 새 위험이다.
> 흔적 ID `TR-xx`는 이 문서가 단일 출처다. 사건 `EV-xx`와 NPC 상태는 [PROGRESSION_AND_ENDINGS.md](PROGRESSION_AND_ENDINGS.md).

## 1. 원칙

1. **현실에 있는 흔적만.** 읽음 표시, 스토리 조회자, 활동 상태, 로그인 알림, 사진·메모 동기화, 기기 간 공유 설정, 찾기 위치. 게임을 위해 지어낸 감시 기능은 없다(P6).
2. **모든 흔적은 피할 방법이 있다.** 오프라인, 설정(활동 상태·읽음 확인·미리보기·동기화·기기 간 공유), 다른 경로(웨이브·튜브·부계정). 흔적을 피하는 법을 아는 것 자체가 "폰을 아는 사람"의 실력이다.
3. **흔적은 벌이 아니라 대화다.** 흔적이 상대를 움직이고, 그 움직임이 정보가 된다. 일부러 흔적을 남겨 상대를 끌어낼 수도 있다(서아의 스토리를 보면 서아가 먼저 DM한다).
4. **반응은 상대가 아는 것 안에서만.** 도현은 슬레이트에 보이는 것만, 실장은 블링크·루프에 보이는 것만 안다([CHARACTERS.md](CHARACTERS.md) 앎 매트릭스).
5. **흔적은 지연될 수 있다.** 오프라인 중 행동의 흔적은 대기했다가 다음 온라인 순간 한꺼번에 간다(현실과 같다).

| TR-01 | 잠금 해제 상태로 첫 온라인 | 도현 | 시러스 보안 알림 "도현의 폰이 온라인 · 잠금 해제됨" | 없음(온라인 = 이것) | DH-1 시작, EV-04~09 |

## 3. 도현의 시야 (슬레이트에서 보이는 것)

| 보이는 것 | 언제 | 도현의 해석 |
|---|---|---|
| 폰 온라인·잠금 해제 | TR-01 | "누가 폰을 열었다. 실장일 수도" |
| 찾기에서 폰 위치 "성원아파트" | 온라인이면 항상 | "…집? 집에 있다고?"(EV-19의 근거) |
| 아빠 톡방 읽음 | TR-02 | "누가 아빠 톡을 봤다" — 실장이면 아빠 이름을 확인하는 중일 수도 |
| 새 사진·스크린샷 | TR-07 | 무엇을 보고 있는지 정확히 안다 |
| 메모·미리 알림 변화 | TR-08 | 상대가 남긴 말 |
| 예약 메일 변화 | TR-09 | 가장 민감 |
| 방해 금지 꺼짐 | TR-12 | "누가 껐다" |
| 녹음 업로드 | TR-13 | "녹음이 살아 있다" — 안도 |
| 부계정 로그인 | TR-10 | "부계정까지 본다" |

**도현이 못 보는 것:** 루프 스토리 조회(자기 계정이지만 남의 스토리 조회 기록은 안 본다), 블링크(폰 한 대 로그인), 은행 앱 사용, 설정 화면 열람, 웹 기록 중 오프라인 것.

## 4. 반응의 리듬 (지연 시간)

현실감은 "바로 반응하지 않는 것"에서 온다. 기본 지연(게임 분):

| 인물 | 흔적 → 반응 | 비고 |
|---|---|---|
| 도현 | 3~8분 | 밤새 깨어 있다. 스크린 타임(슬레이트)으로 깨어 있는지 보인다 |
| 지훈 | 2~5분(01:00~07:00는 30분 이상, 잔다) | |
| 서아 | 10~20분 | 망설인다. 입력 중 표시가 나타났다 사라진다 |
| 실장 | 10~40분 | 바로 움직이지 않는다. 계정 정리부터 |
| 민지 | 5~15분(03:00 이후 무응답) | |
| 하린 | 1회만, 30분 | |
| 김태윤 | 메일: 다음 날 08:10 일괄 답장(새벽엔 안 읽는다) | |

## 5. 흔적을 일부러 남기기 (전략 예시)

| 의도 | 행동 | 결과 |
|---|---|---|
| 서아를 먼저 말하게 | 서아 스토리를 본다(TR-05) | 서아 DM "도현아? 너야? 나 경찰한테…" — 서아가 먼저 거짓말을 꺼낸다 |
| 도현에게 "아빠"라고 알리기 | 아빠 톡방을 연다 / 카메라로 방을 찍는다(동기화 켜짐) | 도현의 의심이 실장에서 아빠로 옮겨 간다(EV-19 앞당김) |
| 실장의 흔적 정리를 늦추기 | 블링크를 미리보기로만 읽는다 | KS-0 유지, 공개 흔적 보존 |
| 도현에게 "어디 있는지 안다"고 알리기 | 한끼 재주문(TR-17) | DH 상태에 따라 신뢰 또는 도주 |

## 6. 설계 규칙

1. 모든 TR은 [PROGRESSION_AND_ENDINGS.md](PROGRESSION_AND_ENDINGS.md)의 반응표와 짝이 있어야 한다(린터 검사, [DATABASE_SCHEMA.md](../04-tech/DATABASE_SCHEMA.md)).
2. 한 흔적의 반응은 한 번만(같은 흔적 반복은 무반응). 단, 경계 누적은 정해진 상한까지.
3. 흔적으로 인한 손실(삭제·도주)에는 반드시 다른 경로가 있다(P4). 확인은 [PRODUCT_PRINCIPLES.md](../00-foundation/PRODUCT_PRINCIPLES.md)의 P4와 [EVIDENCE_LEDGER.md](EVIDENCE_LEDGER.md)의 보존 수단 표를 대조한다.
4. 흔적 알림을 플레이어에게 "경고"로 띄우지 않는다. 플레이어는 상대의 반응을 보고서야 흔적이 갔다는 걸 안다. 단, 처음 한 번은 반응이 분명하게 오도록 설계한다(서아의 "봤네?" DM, 지훈의 "읽었잖아").

## 확인 사항

- TR-06의 "블링크 읽기 → KS-1"은 블링크 앱을 열어 읽는 경우를 뜻하고, 잠금화면 미리보기 "항상"으로 본문을 읽는 V-15는 KS-0을 유지한다. 콘텐츠 데이터에서 두 경우를 구분해 구현해야 한다(Q-OPEN-01).
- TR-02의 "알림 미리보기로만 읽기"는 읽음 표시를 남기지 않는 것으로 읽힌다. 미리보기 열람이 "읽음"으로 집계되는 앱(톡·메시지)과 아닌 앱(블링크)의 경계가 콘텐츠 데이터에 명시되어야 한다(Q-OPEN-02).
