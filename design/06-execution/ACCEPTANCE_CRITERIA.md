## 0. 판정 규칙과 검증 방법

1. 모든 AC는 **Given(전제) / When(행동) / Then(관찰)** 형식이다. "느낌"이 아니라 화면·상태·파일에서 확인 가능한 값으로 판정한다.
2. 판정 문구 금지: 화면에 "정답", "틀렸습니다", "판정", "성공", "새 단서", "획득"이 0건이어야 한다. 세계의 반응만 온다.
3. 게임은 플레이어가 근거를 봤는지(`seen`)를 판정에 쓰지 않는다. 근거를 보지 않아도 올바른 입력이면 성립한다([`ACTION_PROOF`](../01-product/ACTION_PROOF.md)).
4. 검증 방법 코드:

| 코드 | 방법 |
|---|---|
| **L0** | Python 콘텐츠 린터 `python3 game/tools/lint_content.py --content game/content --strict` |
| **U** | Playwright로 `game/tests/unit.html`을 열어 순수 함수·상태 전이 검사(테스트 이름: `clock`, `visibility`, `net`, `verify`, `trace`, `morph`, `save`, `endings`, `hints`, `dialogue`, `composer`) |
| **P** | Playwright 경로 테스트 `route_a.js`, `route_a2.js`, `route_b.js`, `route_c.js`, `route_d.js`, `crisis.js`, `traces.js`, `moved.js`, 단계 게이트 `p1_shell.spec.js`, `p2_reaction.spec.js`, `route_side.js` |
| **V** | 시각 회귀 `visual.spec.js`(390×844, 다크·라이트, 애니메이션 끔) |
| **M** | 수동 검사(문서·화면 확인, 플레이테스트) |
| **D** | iPhone Safari 실기기(가능하면 iPhone SE 1대 포함) |

5. 공통 불변식: 페이지 에러 0, 콘솔 에러 0, 외부 네트워크 요청 0, 판정 문구 0, 세이브/복원 후 같은 화면·같은 상태. 모든 경로 테스트에 적용한다.
6. MVP/본편 구분은 [`IMPLEMENTATION_ROADMAP`](./IMPLEMENTATION_ROADMAP.md) 2절을 따른다. 본편 전용 AC는 "P8"로 표시한다.
