# SCREEN_SPECIFICATIONS — 공통 화면 패턴과 셸·톡·블링크 P0

> **역할:** LUMA OS 화면의 **레이아웃 수치 단일 출처 중 첫 번째 파일**이다. P1 화면이 참조하는 공통 화면 패턴 A~H를 정의하고, 셸·톡·블링크의 P0 화면을 14항목 밀도로 확정한다.
> **단일 출처:** 이 파일 = 공통 패턴 A~H, `SCR-OS-*`·`SCR-PAUSE-*`·`SCR-TALK-*`·`SCR-BLINK-*` P0 화면의 영역 y좌표·높이·간격·표시 데이터. 화면 ID·부모·표시 방식은 [NAVIGATION_ARCHITECTURE.md](./NAVIGATION_ARCHITECTURE.md), 컴포넌트 구조는 [COMPONENT_SPECIFICATIONS.md](./COMPONENT_SPECIFICATIONS.md), 값은 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md), 전환·제스처는 [INTERACTION_SPECIFICATIONS.md](./INTERACTION_SPECIFICATIONS.md)가 단일 출처다.
> **참조:** [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) · [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md) · [RESPONSIVE_DESIGN.md](./RESPONSIVE_DESIGN.md) · [ACCESSIBILITY.md](./ACCESSIBILITY.md) · [ICONOGRAPHY_AND_IMAGERY.md](./ICONOGRAPHY_AND_IMAGERY.md) · [SYSTEM_SHELL_SPECIFICATION.md](../03-features/SYSTEM_SHELL_SPECIFICATION.md) · [MESSAGING_SPECIFICATION.md](../03-features/MESSAGING_SPECIFICATION.md) · [SECURE_MESSAGING_SPECIFICATION.md](../03-features/SECURE_MESSAGING_SPECIFICATION.md) · [BUSINESS_RULES.md](../01-product/BUSINESS_RULES.md) · [TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md) · [EVIDENCE_LEDGER.md](../01-product/EVIDENCE_LEDGER.md).
> **근거:** 공통 지시서 3.2~3.4, [NAVIGATION_ARCHITECTURE.md](./NAVIGATION_ARCHITECTURE.md) 3절 화면 인벤토리 확정본, 03-features의 셸·톡·블링크 데이터. 이 문서는 캐논에 없는 이야기 사실·단서·인물을 만들지 않는다. 구조를 채우는 장식 데이터는 "(장식, 단서 아님)"으로 표시한다.

## 0. 이 문서를 읽는 법

### 0.1 화면 명세의 세 파일

화면 명세는 역할별로 세 파일로 나뉜다. 한 화면의 상세는 반드시 한 파일에만 있다.

| 파일 | 담당 | 상세 밀도 |
|---|---|---|
| **SCREEN_SPECIFICATIONS.md** (이 파일) | 공통 패턴 A~H + 셸·톡·블링크 P0 | P0는 14항목 전부, 공통 패턴은 치수표 |
| [SCREEN_SPECIFICATIONS_SNS_SETTINGS.md](./SCREEN_SPECIFICATIONS_SNS_SETTINGS.md) | 루프 P0 9개 + 설정 P0 6개 | P0는 14항목 전부 |
| [SCREEN_SPECIFICATIONS_APPS.md](./SCREEN_SPECIFICATIONS_APPS.md) | 나머지 P1 전부(139개) | 화면당 표 1개(14항목을 행으로), 공통 패턴은 "패턴 X 따름"으로 참조 |

- P0는 34개다. 셸·일시정지 11 + 통신 8 + SNS 9 + 설정 6 = 34. 이 파일은 그중 셸·톡·블링크 19개를 다룬다. 여기에 작업 지시서가 P0 밀도를 요구한 5개(`SCR-OS-APP-SWITCHER`, `SCR-TALK-ROOM-SETTINGS`, `SCR-PAUSE-HINT`, `SCR-PAUSE-SETTINGS`, `SCR-PAUSE-SAVE`)를 더해 **24개 SCR ID**를 다룬다.
- `P1*` 표시는 [NAVIGATION_ARCHITECTURE.md](./NAVIGATION_ARCHITECTURE.md) 인벤토리 우선순위가 P1이지만, 이 작업 지시서가 P0 밀도 상세를 요구한 화면이다. 우선순위 자체를 바꾸지 않는다.
- 알림 배너와 길게 누르기 맥락 메뉴는 `SCR-`가 없는 **시스템 표면**이다. 화면 인벤토리에 넣지 않고 이 파일 3.6·3.13에서 표면으로 명세한다.

### 0.2 표기 규칙

| 표기 | 뜻 |
|---|---|
| **y** | 기준 프레임 390×844에서 화면 위쪽부터의 세로 좌표(CSS px = pt). `y 47–91`은 위 47, 높이 44다. |
| **패턴 A~H** | 2절의 공통 화면 패턴. P1 화면은 "패턴 B 따름"처럼 참조한다. |
| **CMP-** | [COMPONENT_SPECIFICATIONS.md](./COMPONENT_SPECIFICATIONS.md)의 컴포넌트 ID. |
| **`--lm-*`** | [DESIGN_TOKENS.md](./DESIGN_TOKENS.md)의 토큰 이름. 값을 새로 만들지 않는다. |
| **P0 14항목** | 1 목적 · 2 진입 경로 · 3 전체 레이아웃 · 4 상단·하단 내비게이션 · 5 주요 컴포넌트 · 6 크기·간격 · 7 타이포·색 · 8 인터랙션 · 9 화면 전환 · 10 데이터 표시 · 11 로딩·빈 화면 · 12 오류·예외 · 13 반응형 · 14 접근성. |
| **TR/E/V/G/F/KS/DH/SA/JH** | 캐논 ID. 값을 바꾸지 않고 링크로만 쓴다. |

- 좌표는 **390×844, 다크 기본**이다. 라이트는 같은 좌표에 색 토큰만 바뀐다. 색은 라이트/다크 값을 함께 적는다.
- 숫자·시각은 캐논 표기 그대로다. 메시지·거래·사진은 절대 시각, 살아 있는 기기 상태만 상대 시각을 쓴다.
- 게임 규칙: 정답 판정 UI·단서 강조·"새 정보" 배지를 만들지 않는다. 정보(i)는 열어야 보인다. 동기화 점의 의미를 설명하지 않는다. 실제 서비스명을 UI 문구에 쓰지 않는다.

## 2. 공통 화면 패턴 A~H

> P1 화면은 이 절의 패턴을 그대로 쓰고, 다른 점만 `SCREEN_SPECIFICATIONS_APPS.md` 표에 적는다. 패턴의 좌표를 화면별로 새로 만들지 않는다.

### 2.1 패턴 A — 탭 루트 목록 화면

**쓰는 곳:** 톡 친구·채팅, 루프 홈·탐색·활동·프로필, 전화 최근 기록·키패드. 앱의 하단 탭이 직접 여는 화면.

```
┌──────────────────────────────────────┐ y 0
│ 상태바 47                             │
├──────────────────────────────────────┤ 47
│ 큰 제목 34/41 700            [동작]   │ 96
│ [선택: 세그먼트 32]                    │
├──────────────────────────────────────┤ 143 / 175
│ ┌──────────────────────────────────┐ │
│ │ 행 72  [썸네일 56] 주 정보       │ │
│ │        보조 정보          배지 시각│ │
│ ├──────────────────────────────────┤ │
│ │ 행 60 …                          │ │
│ └──────────────────────────────────┘ │
│              (세로 스크롤)             │
├──────────────────────────────────────┤ 761
│ 탭 49  (3~5개)                        │
│ 안전영역 34                           │ 810
└──────────────────────────────────────┘ 844
```

| 항목 | 값 |
|---|---|
| 좌우 여백 | `--lm-side` 16 |
| 큰 제목 | y 47–143, `--lm-text-large-title` 34/41 700, 자간 -0.4, 좌우 16 |
| 세그먼트 | y 143–175, 높이 32, 트랙 `--lm-fill`, 썸 `--lm-bg-elevated` |
| 목록 시작 | 세그먼트 없으면 143, 있으면 175 |
| 행 | 44(1줄) / 60(2줄) / 72(썸네일). 썸네일 56, 텍스트 시작 = 썸네일 오른쪽 + 12 |
| 구분선 | `--lm-separator-w` 0.5, 왼쪽 들여쓰기 = 텍스트 시작점 |
| 하단 패딩 | 49 + `--lm-tabbar-safe-h` 34 = 83. 마지막 행이 탭 바에 가리지 않는다 |
| 스크롤 | 본문만. 큰 제목은 스크롤 시 `headline`으로 축소 |
| 빈 상태 | 목록 영역 상단 `--lm-space-12` 48부터 `CMP-EMPTY-STATE` |

- 탭은 `tablist` + 3~5개 `tab`. 탭별 스택·스크롤을 기억한다. 재탭은 맨 위로.
- 앱 루트는 큰 제목과 탭 바를 함께 쓴다(일반 내비 바를 겹치지 않는다).

│ 콘텐츠 (스크롤)                        │
│                                       │
├──────────────────────────────────────┤ 758 / 766
│ [선택: 작성창 52 / 액션 바 44]         │
│ 안전영역 34                           │ 810
└──────────────────────────────────────┘ 844

| 항목 | 값 |
|---|---|

### 2.3 패턴 C — 큰 제목 그룹 목록(설정형)

**쓰는 곳:** 설정 루트·하위, 블링크 설정·개인정보, 앱 정보·메뉴.

│ ├──────────────────────────────────┤ │
│ │ 행 44                            │ │

| 항목 | 값 |
|---|---|
| 큰 제목 | y 47–143, 좌우 16, 필요 시 검색 필드 36(터치 44) |

### 2.4 패턴 D — 전체 화면 미디어 뷰어

**쓰는 곳:** 사진 뷰어, 버스트, 영상 시청, 스크린샷 확대.

│                                       │

| 항목 | 값 |
|---|---|
| 배경 | 검정 `#000000` 고정. 라이트에서도 검정 |
| 상단 크롬 | y 0–91(상태바 숨김 변형은 47–91). 닫기·확대 상태·더보기 각 44 |
| 미디어 | 남은 높이에 맞춤. 원본 비율 유지, 잘라내지 않음 |

### 2.5 패턴 E — 시트

**쓰는 곳:** 공유, 정보(i), 필터, 액션 시트, 서랍, 앱별 짧은 선택.

```
┌──────────────────────────────────────┐ 0
│ (배경 scrim 0.48)                     │
│                                       │
├────────────  ─── 24×5 손잡이          │ 380 (중간)
│  제목 22/28 700                  닫기 │
│  내용                                 │
│                                       │
└──────────────────────────────────────┘ 844
```

| 단계 | 위 y | 높이 | 쓰는 곳 |
|---|---|---|---|
| 작은 | 633 | 211 | 짧은 선택·필터 |
| 중간 | 380 | 464 | 공유·정보(i)·대화 정보 |
| 큰 | 84 | 760 | 서랍·목록 탐색 |

### 3.1 SCR-OS-LOCK — 잠금화면

**1. 목적** 잠금 해제 전에도 볼 수 있는 것(응급정보·카메라·알림 미리보기)을 보여 주고, 6자리 암호로 T0을 끝낸다.

**2. 진입 경로** 부팅 / 잠금. 뒤로 가기 없음. 알림·카드 탭은 `SCR-OS-PASSCODE`를 먼저 연다.

**3. 전체 레이아웃**

**4. 상단·하단 내비게이션** 상태바·내비 없음. 하단 고정: 왼쪽 "응급"(44 터치, x=16), 오른쪽 "카메라"(44, x=330). 홈 인디케이터 장식.

**5. 주요 컴포넌트** `CMP-STATUS-BAR`(숨김 변형) · `CMP-WIDGET`(분실 모드 카드 변형) · `CMP-NOTIFICATION-CARD` · `CMP-LOST-MODE-CARD` · `CMP-ICON-BUTTON`.

**6. 크기·간격** 카드 좌우 16, 폭 358, 모서리 `--lm-radius-lg` 20(분실 카드)·`lg`(알림). 카드 사이 8. 시계 아래 날짜 8. 날짜 아래 카드 16.

**7. 타이포·색** 배경은 배경화면 사진(2019년 가족사진, E-30) 위 scrim 0.48. 시계 `--lm-text-display-clock` 76/80 300 `--lm-label`. 날짜 `subhead` `label-2`. 카드 `--lm-material-regular` + `elev-2`(라이트), 글자 `--lm-label`, 보조 `--lm-label-2`, 자물쇠 `--lm-label-2`. 라이트/다크 모두 배경화면 위 글자는 scrim으로 대비 확보.

**8. 인터랙션** 시계·빈 곳 탭 = `SCR-OS-PASSCODE`. 알림 카드 탭 = 키패드 먼저. 분실 카드 [통화] = "서비스 없음" 시트(성공처럼 보이지 않음). 응급 = `SCR-OS-EMERGENCY`. 카메라 = `SCR-CAM-VIEWFINDER`(찍기만). 아래로 끌기·제어 센터·검색은 잠금 중 열리지 않는다. 흔적: 잠금 해제는 TR-01, E-07.

**9. 화면 전환** → `SCR-OS-PASSCODE` modal 350ms `ease-sheet` / → `SCR-OS-EMERGENCY` modal / → `SCR-CAM-VIEWFINDER` push. 암호 성공 시 → `SCR-OS-HOME`, 연출 없음.

**10. 데이터 표시** 시각 `21:10`(24시간, tnum), 날짜 `3월 17일 화요일`. 분실 카드 "이 폰을 주우셨다면 연락 부탁드립니다. 010-XXXX-2290". 알림 23개는 시간 역순·앱별 묶음. 캐논 예: 은행 "…지급정지…", 경찰 "[성원경찰서] 이도현님…", 지훈 "야 너 어디야 전화 좀 받아". 블링크·루프 DM은 "새 메시지"만. 위젯 "다음 일정: 3/16 입실"(지난 일정, 회색). 배터리 31% 충전 중. 긴 텍스트는 1줄 말줄임(미리보기), 앱 이름·시각 고정.

**11. 로딩·빈 화면** 알림이 0개면 "알림이 없습니다"만. 로딩 없음(캐시 즉시). 위젯 데이터가 없으면 위젯을 숨기고 시계·알림만.

**12. 오류·예외** 오프라인: 알림 수신 없음, 기존 더미 유지. 통화 시도: "서비스 없음. 이 기기에서는 전화와 문자를 쓸 수 없습니다." 원격 지우기 진행 중이면 이 화면의 시스템 상태로 8초 진행 화면, 입력 차단. 잠금 대기 30초. 잠금 초기화 없음.

**13. 반응형** 320: 시계 `clamp(64px, 19.5vw, 98.8px)`, 카드 좌우 16 유지. 430: 카드 폭 398. 높이 667: 알림 카드 4장→3장, 간격 8 유지, 하단 버튼 y 640. 글자 4단계: 시계는 최대 98.8, 카드 본문은 1.3배에서 2줄까지. xl에서도 320 가로 스크롤 없음.

**14. 접근성** 잠금화면 `h1`은 "잠금화면". 읽기 순서: 날짜 → 시각 → 알림 23개 → 분실 카드 → 응급정보 → 카메라 → 암호 입력. 응급정보 44×44. 알림 카드는 `button`. 시계 `<time datetime>`. 스크린리더: "3월 17일 화요일, 21시 10분. 알림 23개. 응급정보 버튼. 암호 6자리 입력." 키패드 없이 물리 숫자 입력 가능. 동작 줄이기에서 배경 패럴랙스 없음.

### 3.2 SCR-OS-PASSCODE — 암호 키패드

**1. 목적** 기기 잠금을 6자리 숫자로 해제한다. 잠금 흐름의 필수 하위 화면이며 성공 연출이 없다.

**2. 진입 경로** `SCR-OS-LOCK` 탭 / 알림 카드 탭 / 잠금 상태 딥링크. 부모 `SCR-OS-LOCK`, modal.

**4. 상단·하단 내비게이션** 상단 오른쪽 닫기(44). 하단 내비 없음. 키패드 마지막 행 왼쪽 "응급"은 `SCR-OS-EMERGENCY`로. 홈 인디케이터 표시.

**5. 주요 컴포넌트** `CMP-PASSCODE-KEYPAD` · `CMP-ICON-BUTTON` · `CMP-STATUS-BAR`.

**6. 크기·간격** 점 12·간격 12. 키 72, 간격 16, 좌우 24. 키패드 폭 248, 좌우 (390−248)/2 = 71. 오류 텍스트와 점 사이 28. 상단 닫기 44.

**7. 타이포·색** 표면 `--lm-bg-elevated`(라이트 #FFFFFF / 다크 #1C1C1F) 또는 `material-thick`. 제목 `title-3` 20/25 600 `label`. 점 채움 `label`, 빈 점 `fill`. 키 배경 `fill`, 키 숫자 `label`. 오류 `destructive-ink`. 대기 `warning-ink`. 라이트/다크 동일 좌표.

**8. 인터랙션** 숫자 탭 = 점 채움. 6자리에서 자동 검증. **070921**이면 즉시 홈. 오답이면 점 흔들림 400ms + "암호가 맞지 않습니다. 다시 입력하세요." 오답 6회째부터 30초 대기, 입력 차단, 남은 초 표시. 대기 중에도 응급정보·카메라 가능. 물리 키보드 숫자·붙여넣기 허용. 흔적: TR-01(해제 후 첫 온라인), E-07/V-01/G-01.

**9. 화면 전환** 성공 → `SCR-OS-HOME` 즉시(페이드 없음). 닫기/뒤로 → `SCR-OS-LOCK`. 응급 → `SCR-OS-EMERGENCY` modal. 딥링크로 열렸으면 성공 후 목표 화면으로 푸시(잠금 우회 없음).

**10. 데이터 표시** 점 6개만. 입력 숫자를 텍스트로 노출하지 않는다. 정답 070921은 응급정보 생년월일 2007.09.21에서 온다. 화면이 그 관계를 설명하지 않는다.

**11. 로딩·빈 화면** 없음. 즉시 입력 가능. 대기 중 카운트다운 외 빈 화면 없음.

**12. 오류·예외** 오답·6회 대기·오프라인 모두 동일. 오프라인에서도 잠금 해제 가능. 원격 지우기 중에는 키패드 입력을 받지 않는다. "암호 찾기"·초기화 버튼 없음.

**13. 반응형** 320: 키 72 유지 시 248+48=296 < 320, 좌우 36. 430: 좌우 91. 높이 667: 키패드 y 250–586, 점 y 180. xl: 키 숫자 22→28.6, 키 72 유지, 가로 스크롤 없음.

**14. 접근성** 키패드 `group` + `aria-label="숫자 키패드"`, 각 키 `button` + 숫자 라벨, `⌫`는 "지우기", 응급은 "응급정보". 6자리 입력 상태를 "6자리 입력됨"으로. 오답 `role=alert`. 대기 남은 초 `aria-live`. 포커스는 키패드 첫 키. Esc = 닫기.
