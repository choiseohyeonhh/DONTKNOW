## 1. Human Interface 원칙의 LUMA 재해석

Apple Human Interface의 원칙을 그대로 베끼지 않고, 이 게임의 조건(아들의 폰 하나, 조사 도구, 실시간 반응)에 맞게 다시 쓴다.

| 원칙 | 원문 요지 | LUMA 재해석 | 이 게임에서의 판정 예 |
|---|---|---|---|
| **명료성(Clarity)** | 글자·아이콘·색이 즉시 읽힌다. 장식이 정보를 가리지 않는다 | 폰을 처음 쥔 아버지가 설명 없이 누를 수 있어야 한다. 모든 조작은 실제 폰 기능의 모양을 닮되, 라벨은 LUMA의 말로 쓴다 | 잠금 해제는 키패드와 응급정보로만. "수사 시작" 같은 게임 버튼을 두지 않는다 |
| **콘텐츠 존중(Deference)** | UI는 물러나고 콘텐츠가 주인공이다 | 화면의 주인공은 사진·메시지·거래 내역이다. 크롬은 반투명하고 낮은 대비로 물러난다. 단, 읽어야 하는 글자는 절대 물러나지 않는다 | 내비 바는 `material-thin`, 목록 배경은 `bg`, 사진은 전체 폭. 배경에 큰 로고·장식을 두지 않는다 |
| **깊이·계층(Depth)** | 겹침·전환·재질로 공간 관계를 만든다 | 깊이는 그림자가 아니라 **면의 밝기와 재질**로 만든다(다크 기본). 시트는 아래에서 올라오고, 푸시는 옆으로 밀린다 | 시트 z=70, 경고창 z=90, 일시정지 z=100. 다크에서 `box-shadow`를 쓰지 않는다 |
| **일관성(Consistency)** | 같은 것은 같게, 다른 것은 다르게 | 같은 동작은 30개 앱에서 같은 제스처·같은 아이콘·같은 문구를 쓴다. 앱마다 다른 것은 **강조색 하나와 정보 구조**뿐이다 | 길게 누르기 = 맥락 메뉴, 왼쪽 가장자리 밀기 = 뒤로, 공유 아이콘은 전 앱 동일 |
| **직접 조작(Direct manipulation)** | 손가락이 대상과 직접 상호작용한다 | 플레이어는 메뉴가 아니라 **대상 자체**를 만진다. 사진을 두 번 탭해 좋아요, 스토리를 넘겨 다음 사람, 사진을 벌려 번호판 판독 | "좋아요" 버튼을 게임이 따로 권하지 않는다. 두 번 탭의 결과가 곧 흔적이다 |
| **피드백(Feedback)** | 모든 조작에 즉시 반응한다 | 누름은 100ms 축소·색 변화, 완료는 160ms 체크, 실패는 문구+아이콘. **게임의 정답 여부는 피드백하지 않는다** | 전송 성공은 말풍선 추가로 보인다. "정답입니다" 피드백은 금지다 |

### 1.1 이 게임에서 원칙보다 우선하는 것

- **P2(추리는 머릿속, 증명은 손끝):** 어떤 시각적 피드백도 플레이어의 추리를 대신 판정하지 않는다. 성공/실패·정답/오답·연결 완료를 UI로 표시하지 않는다.
- **P3(보는 것도 흔적):** 시각적으로 조용한 화면일수록 플레이어는 더 많이 본다. 그러나 그 행동은 상대에게 간다. UI는 이 사실을 설명하지 않는다.
- **P5(감정은 데이터가 말한다):** 색·아이콘·문구로 감정을 설명하지 않는다. 지워진 항목, 읽지 않은 "1", 03:58 같은 시각이 감정을 만든다.

## 2. 시각 정체성: 유리 한 장

화면 밖 레이어는 없다. 화면에는 **아들의 폰, 유리 한 장**만 있다.

| | LUMA OS (아들의 폰) | 폰 밖(데스크톱 여백·프롤로그·엔딩) |
|---|---|---|
| 질감 | 평평한 면, 정확한 선, 미세한 반투명 | 도현의 방 책상: 나뭇결, 스탠드 불빛, 충전 케이블. 정보 없음 |
| 색 | 차가운 중성 + 앱별 단색 | 따뜻한 저조도(스탠드 2700K) |
| 글꼴 | Pretendard, 숫자 tnum | 자막만 Pretendard |
| 움직임 | 짧고 정확(160~240ms, ease-out) | 없음(정지 배경) |
| 감정 | 무표정. 데이터는 감정이 없다 | 아버지가 앉아 있는 자리. 사람은 보이지 않는다 |

- **대표 구도:** 어두운 방, 스탠드 아래 충전기에 꽂힌 폰 한 대. 화면에 "1"이 붙은 아빠 톡방. 키 비주얼·스토어 스크린샷의 기준 구도다.
- **금지:** 그라데이션 장식, 광택, 3D, 유리 반사 이미지, 종이 질감, 손글씨 UI. 유리는 **재질(블러)** 로만 표현하고, 유리처럼 빛나는 장식을 그리지 않는다.
- 폰 밖 배경은 정보가 아니다. 배경에 단서·글자·사물 라벨을 추가하지 않는다.

## 3. 정보 위계

### 3.1 층

| 층 | 요소 | 시각 규칙 |
|---|---|---|
| L0 | 상태바 | 가장 낮은 대비. `label-2` 크기 12. 정보는 시각·회선·Wi-Fi·배터리만 |
| L1 | 화면 제목 | `large-title` 또는 `title-1`. 화면당 하나 |
| L2 | 섹션 제목 | `title-3` 또는 `headline`. 그룹 사이 24 여백 |
| L3 | 행 주 정보 | `headline` 또는 `body`. 17pt |
| L4 | 행 보조 정보 | `subhead` 또는 `footnote`. `label-2` |
| L5 | 메타데이터 | `caption-1`/`caption-2`. `label-3`은 장식에만 |
| L6 | 크롬 동작 | 아이콘 17/20/24. `tint` |

### 3.2 규칙

1. 한 화면에 L1 제목은 하나다. 두 개가 필요하면 상세 화면으로 푸시한다.
2. 한 행 안에서 글자 스타일은 최대 두 개다(주 정보 + 보조 정보).
3. 숫자는 항상 `tabular-nums`다. 목록의 시각·금액·개수는 오른쪽 정렬한다.
4. 읽어야 하는 정보에 `label-3`를 쓰지 않는다. `label-3`는 플레이스홀더·비활성·장식 전용이다.
5. 정보(i)로만 보이는 값은 화면에 미리 요약해 두지 않는다. 위계를 위해 숨기는 것이 아니라, **열어야 보이는 것**이 게임 규칙이다.

## 4. 색 사용 규칙

| 규칙 | 내용 | 예외 |
|---|---|---|
| **강조색은 화면당 하나** | 한 화면에서 `tint` 또는 `--lm-app-tint` 중 하나만 강조색으로 쓴다 | 상태 점(성공·경고·파괴)은 강조색으로 세지 않는다 |
| **앱 색은 앱 안에서만** | `--lm-app-tint`는 그 앱의 말풍선·선택 세그먼트·전송 버튼·강조 점에만 쓴다 | 알림 배너의 앱 아이콘 타일은 타일색을 쓴다 |
| **빨강은 파괴적 동작만** | `destructive`는 삭제·차단·초기화·원격 지우기 확인에만 쓴다 | 오류 문구의 아이콘은 `destructive`, 본문은 `label` |
| **상태는 점으로** | 성공·경고·오류는 8pt 점 + 텍스트 라벨로 표시한다 | 큰 배지가 필요하면 `success`/`warning` 채움 + `on-status` 글자 |
| **색만으로 상태를 표시하지 않는다** | 연결됨/끊김, 읽음/안 읽음, 온라인/오프라인은 항상 아이콘·문구·굵기를 함께 쓴다 | 해당 없음 |
| **그라데이션 금지** | UI 면·버튼·아이콘에 장식 그라데이션을 쓰지 않는다 | 배경화면 사진, 카메라 뷰파인더의 자연스러운 명암 |
| **순수 검정** | `#000000`은 다크 모드 배경에만 쓴다 | 라이트 모드, 카드, 텍스트 |

- `tint-fill`을 큰 면적 배경으로 쓸 때 글자는 반드시 `on-tint`다. `tint`는 큰 글자·아이콘·테두리에만 쓴다.
- `destructive`를 텍스트로 쓰지 않는다. 본문 크기 파괴적 텍스트는 `destructive-ink`, 파괴적 버튼 채움은 `destructive-fill` + `on-tint`다.
- 앱 tint 30종의 on-tint 조합은 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md) 8절 표를 그대로 쓴다.

## 6. 여백과 그리드

### 6.1 기준

- 4pt 기준. 토큰은 2, 4, 8, 12, 16, 20, 24, 32, 40, 48이다.
- 화면 좌우 기본 여백은 16이다.
- 섹션 사이 24, 그룹 안 셀 사이 0(구분선), 카드 내부 12~16, 카드 사이 12.
- 전체 폭 예외: 사진·지도·카메라 뷰파인더·시네마틱 스틸·홈 배경화면.

### 6.2 목록

| 유형 | 행 높이 | 좌우 | 구분선 |
|---|---|---|---|
| 1줄 텍스트 | 44 | 16 | 텍스트 시작점에서 오른쪽 끝까지 |
| 2줄 텍스트 | 60 | 16 | 같음 |
| 썸네일 + 2줄 | 72 | 16 | 썸네일 오른쪽 + 12에서 시작 |
| 그룹 목록 | 위 값 | 셀 내부 16 | 셀 사이 0.5, 그룹 바깥 24 |

- 카드형 남발 금지. 기본은 목록이다. 카드는 사진·게시물·요약처럼 묶음이 필요한 곳에만.

### 6.3 그리드

| 그리드 | 열 | 간격 | 좌우 여백 | 셀 계산(390 기준) |
|---|---|---|---|---|
| 사진 앱 그리드 | 3 | 2 | 0(전체 폭) | (390 − 2×2) ÷ 3 = 128.67 |
| 탐색 탭 그리드 | 3 | 2 | 0(전체 폭) | 128.67 |
| 프로필 태그됨 그리드 | 3 | 2 | 0(전체 폭) | 128.67 |
| 앨범 카드 그리드 | 2 | 12 | 16 | (390 − 32 − 12) ÷ 2 = 173 |
| 홈 아이콘 | 4 | 계산값 | 16 | 아래 6.4 |

### 6.4 홈 아이콘 그리드

- **4열 × 5행 + 독 4칸**(캐논). 페이지당 20칸, 페이지 3장(60칸 ≥ 앱 30종 + 폴더). 모든 높이에서 5행 고정. 짧은 높이 검수는 [RESPONSIVE_DESIGN.md](./RESPONSIVE_DESIGN.md) 2.2.
- 아이콘 타일 60×60, 모서리 `--lm-radius-icon` 13.5(슈퍼타원 n=4.6).
- 라벨은 `caption-1` 12/16, 타일 아래 4, 최대 1줄 말줄임. 셀 높이 = 60 + 4 + 18 = 82.
- 열 간격 = (콘텐츠 폭 − 4 × 60) ÷ 3. 콘텐츠 폭 = 화면 폭 − 2 × 16.
  - 390: (358 − 240) ÷ 3 = **39.33**
  - 320: (288 − 240) ÷ 3 = **16**
  - 430: (398 − 240) ÷ 3 = **52.67**
- 행 간격 18. 5행 높이 = 5 × 82 + 4 × 18 = **482**.
- 독: 4칸, 같은 60 아이콘과 같은 열 간격. 배경 `material-thick`, 모서리 28, 위아래 패딩 12. 높이 84. 화면 좌우 16.
- 홈 인디케이터: 134×5, 하단 8.
- 세로 배치(844 기준): 상태바 47 + 상단 12 + 482 + 페이지 점 16 + 독 84 + 인디케이터 21 = 662. 남는 182는 격자 위쪽 위젯 줄(높이 최대 158)과 여백으로 쓴다. 위젯이 없는 페이지는 격자를 세로 중앙 정렬한다.

## 7. 레이아웃 시스템

### 7.1 안전영역

- 상단: `--lm-safe-top`이 0보다 크면 `safe-top + 44`를 상태바로 쓴다. 0이면 47을 쓴다.
- 하단: 탭 바는 49 + `max(34, safe-bottom)`이다. 홈 인디케이터는 safe-bottom 위 8에 놓는다.
- 콘텐츠는 안전영역을 침범하지 않는다. 전체 폭 미디어만 안전영역까지 확장할 수 있다.
- 키보드가 열리면 `visualViewport` 기준으로 콘텐츠를 줄이고, 입력 필드는 키보드 위 16에 둔다.

### 7.2 크롬 스택

| 층 | 높이 | z-index | 재질 |
|---|---|---|---|
| 상태바 | 47(실기기 safe-top+44) | 10 | `material-thin` |
| 내비 바 | 44, 큰 제목 96 | 10 | `material-thin` |
| 콘텐츠 | 남은 높이 | 0 | `bg` |
| 탭 바 | 49 + 하단 안전영역 | 20 | `material-regular` |
| 배너 | 콘텐츠 위 | 60 | `material-regular` + `elev-2`(라이트) |
| 시트 | 가변 | 70 | `material-thick` + `elev-3`(라이트) |

- 스크롤 콘텐츠는 상태바·내비 아래로 지나가되, 내비 바가 재질로 가린다.
- 탭 바가 있는 앱은 콘텐츠 하단에 `49 + safe-bottom`만큼 패딩을 준다. 마지막 행이 탭 바에 가리지 않게 한다.

## 8. 모서리·그림자·재질 사용 규칙

| 요소 | 모서리 | 그림자(라이트) | 재질 |
|---|---|---|---|
| 앱 아이콘 타일 | `radius-icon` 13.5 | 없음 | 없음 |
| 버튼·입력 | `radius-sm` 10 | 없음 | 필요 시 `fill` |
| 카드 | `radius-md` 14 | `elev-1` | 불투명 `bg-elevated` |
| 그룹 목록 | `radius-md` 14 (그룹 바깥) | 없음 | 불투명 `bg-elevated` |
| 알림 배너 | `radius-lg` 20 | `elev-2` | `material-regular` |
| 시트 | 위 `radius-xl` 28, 아래 0 | `elev-3` | `material-thick` |
| 경고창 | `radius-lg` 20 | `elev-3` | 불투명 `bg-elevated` |
| 독 | `radius-xl` 28 | `elev-2` | `material-thick` |
| 말풍선 | `radius-bubble` 18 | 없음 | 불투명 앱 tint/bg-tertiary |
| 태그·칩 | `radius-xs` 6 또는 `full` | 없음 | `fill-2` |

- 다크에서는 `elev-*`가 `none`이다. 깊이는 `bg` → `bg-elevated` → `bg-tertiary` 순서의 면 밝기와 재질로 만든다.
- 재질은 겹치는 크롬(상태바·내비·탭·시트)에만 쓴다. 목록 셀에 블러를 쓰지 않는다.
- 블러 미지원 시 불투명 `bg-elevated`로 대체한다. 이때도 레이아웃은 변하지 않는다.

## 9. 다크 모드 원칙

1. **기본은 다크.** 도현의 폰 설정이며, 게임은 다크로 시작한다.
2. **순수 검정은 OLED 다크에서만.** 다크 배경 `#000000`은 OLED 절전과 "꺼진 유리" 느낌을 위한 것이다. 라이트 모드·카드·텍스트에는 쓰지 않는다.
3. **그림자 대신 면 밝기.** 다크에서 `elev-*`는 `none`이고, 카드는 `bg-elevated`, 눌린 면·보조 면은 `bg-tertiary`로 구분한다.
4. **재질은 어둡게.** 다크 재질은 `rgba(28,28,31,α)`다. 라이트 재질 색을 다크에 쓰지 않는다.
5. **사진은 그대로.** 사진·영상에 다크 필터를 씌우지 않는다. UI 크롬만 어두워진다.
6. **대비 유지.** 다크에서 `label`/`bg`는 19.29:1, `label-2`/`bg`는 6.79:1이다. 라이트의 `label-2`처럼 낮은 대비를 다크에서 흉내 내지 않는다.
7. **전환.** 라이트/다크/자동 전환은 설정 > 디스플레이에서 제공한다. 전환 시 240ms 크로스페이드 1회, 레이아웃 이동 없음. "플레이어 전환 허용 여부"는 [OPEN_QUESTIONS.md](../06-execution/OPEN_QUESTIONS.md)로 넘긴다(추천: 허용, 스토리 영향 없음).

## 10. iOS 복제 금지 경계

이 절은 **레퍼런스 분석**이다. 실제 서비스명은 여기서만 쓴다. 게임 UI 문구·아이콘·화면에는 쓰지 않는다.

| 항목 | 따르는 것(관용적 기대) | 바꾸는 것(LUMA) | 금지 |
|---|---|---|---|
| 상태바 | 왼쪽 시각, 오른쪽 연결·배터리 | 회선 "서비스 없음" 고정, 동기화 점 추가, 아이콘 12pt 모노라인 | iOS 상태바 아이콘 복사 |
| 홈 | 아이콘 격자 + 독 + 페이지 | 4×5 + 독 4칸, 3페이지, 앱 배치가 도현의 습관을 보여 줌 | iOS 격자·독 배치 그대로, 앱 이름·아이콘 복제 |
| 내비게이션 | 뒤로·제목·동작, 큰 제목 축소 | 제목 스타일·재질·아이콘은 LUMA 토큰 | iOS 대형 제목 애니메이션 복제 |
| 탭 바 | 하단 5개 이하, 아이콘+라벨 | 49+안전영역, 앱별 3~5개, 라벨 12pt | iOS 탭 바 높이·블러 그대로 |
| 목록 | 행·구분선·셰브런 | 행 44/60/72, 구분선 들여쓰기 규칙, 카드 남발 금지 | iOS 설정 화면 복제 |
| 시트 | 하단에서 올라오는 카드 | 위 모서리 28, `ease-sheet` 350ms, `material-thick` | iOS 시트 모서리·그랩바 복제 |
| 아이콘 | 24 격자, 단색, 둥근 끝 | 30종 손작업 글리프, 타일 60, 강조점 1개 | SF Symbols, Apple 에셋, 생성 이미지 |
