# INTERACTION_SPECIFICATIONS — 마이크로 인터랙션과 전환

> **역할:** 화면 전환, 터치 피드백, 제스처, 상태 피드백, 시간 기반 연출, 동작 줄이기 대체를 **트리거·지속·곡선·상태 변화·접근성 대체** 단위로 정의한다. 구현자가 감으로 정하지 않게 한다.
> **단일 출처:** 이 문서 = 화면 푸시/팝·모달·시트·오버레이 전환, 탭 피드백, 길게 누르기, 스와이프, 두 번 탭, 당겨서 새로고침, 로딩·성공·실패·빈 상태, 알림 배너, 동기화 삭제, 읽음 "1", 스토리 진행, 블링크 60초, 스크린샷·화면 기록 표시, 잠금 해제, 키보드, 일시정지, 다크/라이트 전환, 햅틱 대체, 동작 줄이기 대체. **컴포넌트 구조**는 [COMPONENT_SPECIFICATIONS.md](./COMPONENT_SPECIFICATIONS.md), **화면 목록**은 [NAVIGATION_ARCHITECTURE.md](./NAVIGATION_ARCHITECTURE.md), **값**은 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md)가 단일 출처다.
> **참조:** [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) · [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md) · [ACCESSIBILITY.md](./ACCESSIBILITY.md) · [RESPONSIVE_DESIGN.md](./RESPONSIVE_DESIGN.md) · [TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md) · [BUSINESS_RULES.md](../01-product/BUSINESS_RULES.md) · 03-features 문서 전체.

## 0. 원칙

1. **움직임은 짧고 정확하다.** 화면 전환·시트만 `--lm-dur-slow` 350ms를 쓰고, 일반 상태 변화는 `--lm-dur-fast` 160ms~`--lm-dur-base` 240ms다. 반복 애니메이션은 초당 3회 이상 깜빡이지 않는다.
2. **게임이 정답을 피드백하지 않는다.** 성공/실패는 "전송·저장·연결"의 기능 상태만 말한다. "정답입니다", "새 정보", "진행도"를 만들지 않는다.
3. **흔적은 조용히 간다.** 읽음·조회·좋아요·캡처가 상대에게 갔다는 시스템 안내를 띄우지 않는다. 결과는 상대의 반응으로만 온다([TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md) 6절).
4. **모든 제스처에는 단일 대체가 있다.** 뒤로 밀기 = 뒤로 버튼, 시트 끌어내리기 = 닫기 버튼, 길게 누르기 = 더보기 버튼, 두 번 탭 좋아요 = 좋아요 버튼, 당겨서 새로고침 = 새로고침 버튼, 핀치 확대 = `+`/`−` 버튼.
5. **동작 줄이기는 정보를 줄이지 않는다.** 이동·확대·축소·흔들림·패럴랙스·자동 스크롤만 없애고, 정보·상태·문구는 그대로 유지한다.

### 0.1 값의 두 종류

| 종류 | 예 | 규칙 |
|---|---|---|
| **디자인 토큰** | `--lm-dur-fast` 160, `--lm-dur-base` 240, `--lm-dur-slow` 350, `--lm-ease-standard`, `--lm-ease-sheet`, `--lm-ease-exit`, `--lm-tap-scale` 0.97 | [DESIGN_TOKENS.md](./DESIGN_TOKENS.md) 값만 쓴다. 새 토큰을 만들지 않는다. |
| **캐논 연출값·게임 규칙값** | 동기화 삭제 페이드 0.4초, 토스트 3초, 알림 배너 4초, 스토리 5초, 블링크 60초, 스크린샷 플래시 100ms, 키패드 흔들림 400ms, 하트 오버레이 600ms | 캐논·03-features가 정한 값이다. 토큰이 아니며 토큰 값을 대체하지 않는다. 문서에 "연출값"으로 표시한다. |

- 두 종류가 같은 항목에 함께 쓰이면 `지속` 칸에 `토큰 / 연출값`을 구분해 적는다. 예: "페이드 `--lm-dur-base` 240ms / 캐논 문구 3초".
- `prefers-reduced-motion: reduce` 또는 게임 설정 "동작 줄이기"가 켜지면, 이 문서의 모든 이동·확대·축소·흔들림은 **150ms 페이드 또는 즉시 상태 변화**로 대체한다. 7절에 항목별 대체표가 있다.

## 1. 화면 전환

### 1.1 푸시·팝

| 항목 | 트리거 | 지속 | 곡선 | 상태 변화 | 접근성 대체 |
|---|---|---|---|---|---|
| **푸시 진입** | 목록→상세, 설정→하위 | `--lm-dur-slow` 350ms | `--lm-ease-sheet` | 새 화면 오른쪽 100%→0. 이전 화면 0→−30% 시차 이동 + 어둡게 10%(scrim 0.10). 이전 화면 스크롤 고정. | 동작 줄이기: 이동 없이 150ms 페이드. 뒤로 버튼 항상 존재. |
| **푸시 복귀(팝)** | 뒤로 버튼·가장자리 밀기·Esc | `--lm-dur-slow` 350ms | `--lm-ease-exit` | 현재 화면 0→100%, 이전 화면 −30%→0, 어둡게 10%→0. 스크롤·선택·필터 복원. | 150ms 페이드. 포커스는 이전 화면의 연 요소로 복귀. |
| **대화형 뒤로** | 왼쪽 가장자리 20px 이내에서 가로 드래그 | 손가락 1:1, 실행/복귀는 `--lm-dur-base` 240ms | 복귀 `--lm-ease-standard`, 실행 `--lm-ease-exit` | 화면이 손가락을 따라 이동. 폭 35% 이상 또는 왼쪽 속도 500px/s 이상이면 실행. 미달이면 240ms로 제자리. | 뒤로 버튼. 동작 줄이기에서는 따라오는 이동 없이 즉시 팝. |
| **탭 내 스택 보존** | 탭 전환 | `--lm-dur-fast` 160ms | `--lm-ease-standard` | 탭 패널 크로스페이드. 각 탭의 스택·스크롤 유지. | 150ms 페이드. `tab`/`tabpanel`로 상태를 읽는다. |

- 푸시 중에는 이전 화면의 입력을 받지 않는다. 뒤로 제스처 중에는 스크롤을 잠근다.
- 팝 후 포커스는 이전 화면의 **연 요소**로 돌아간다. 목록이면 마지막으로 열었던 행이다.
- 앱 루트에서 뒤로 가면 홈으로 간다. 이때는 푸시 팝이 아니라 **페이드 아웃 240ms**다.

- 시트 위에 시트를 쌓지 않는다. 새 시트가 필요하면 기존 시트를 닫고 연다.

| 시네마틱 컷 | 240ms 크로스페이드 | 150ms 페이드. |
| 동기화 점 | 1.2초 깜빡임(1↔0.35) | 깜빡이지 않음. 유휴 0.35 / 전송 1. |

- 동작 줄이기는 게임 진행·정보에 영향을 주지 않는다. 상태 문구와 수치는 그대로 유지한다.

## 7. 검수 체크

- [ ] 화면 푸시가 350ms `ease-sheet`, 이전 화면 −30%·10% 어둡게인가.
- [ ] 시트 닫기 임계가 거리 30% 또는 속도 800px/s인가.
- [ ] 뒤로 밀기 시작 가장자리가 20px, 임계가 35% 또는 500px/s인가.
- [ ] 탭 축소가 0.97·100ms이고 목록 행은 축소하지 않는가.
- [ ] 길게 누르기가 500ms이고 단일 탭 대체가 있는가.
- [ ] 두 번 탭 좋아요가 사진 게시물에만, 하트 600ms인가.
- [ ] 당겨서 새로고침이 온라인에서만, 오프라인에서 "오프라인"인가.
- [ ] 스켈레톤이 300ms 이후에만 나오는가.
- [ ] 알림 배너가 4초이고 탭이 딥링크인가.
- [ ] 동기화 삭제가 0.4초 페이드 + 3초 문구인가.
- [ ] 읽음 "1"이 160ms에 사라지고 오프라인에서 "읽음 대기"인가.
- [ ] 스토리가 5초/사진, 좌 30%·우 70%, 길게 눌러 정지인가.
- [ ] 블링크 타이머가 60초 원형 감소, 0에서 0.4초 페이드인가.
- [ ] 스크린샷이 100ms·최대 0.35 밝기, 썸네일 3초인가.
- [ ] 화면 기록이 빨간 점 + "기록" 글자인가.
- [ ] 잠금 오답 흔들림 400ms, 6회째 30초 대기인가.
- [ ] 키보드 300ms, 다크/라이트 240ms인가.
- [ ] 동작 줄이기에서 이동·축소·흔들림이 모두 사라지고 정보가 유지되는가.
- [ ] 의도치 않은 흔적에 확인창·경고가 없는가.

## 8. 확인 사항

- (해결) 로딩 표시 기준은 300ms로 통일(UI_UX_GUIDELINES 3.1).
- (해결) 스크린샷 플래시는 100ms·최대 불투명도 0.35로 통일(ACCESSIBILITY 9.2 준수).
- **Q-OPEN-223:** 스토리 자동 진행을 5초/사진으로 정했다. [ACCESSIBILITY.md](./ACCESSIBILITY.md) 5.1은 "자동 넘김 끄기"를 요구한다. 이 문서는 자동 넘김 끄기 설정을 제공하는 것으로 해결했다. 기본값을 자동 켜짐/꺼짐 중 무엇으로 할지 확정이 필요하다. 추천: 기본 켜짐, 설정에서 끄기.
- **Q-OPEN-224:** 시트 끌어내리기 임계(높이 30% 또는 아래 속도 800px/s)와 뒤로 밀기 속도 임계(500px/s)는 캐논에 없는 **설계값**이다. 구현 감각에 맞는지 확인이 필요하다.
- **Q-OPEN-225:** 두 번 탭 좋아요 판정 창을 300ms로 정했다. [ACCESSIBILITY.md](./ACCESSIBILITY.md) 10절의 사진 두 번 탭 확대와 같은 300ms다. 루프 사진 게시물에서는 두 번 탭이 좋아요이고 확대는 핀치·`+` 버튼이므로 충돌하지 않지만, 사진 앱과 루프의 제스처 차이를 사용자가 혼동할 수 있다. 안내 문구를 넣지 않는 현재 원칙과 함께 확인이 필요하다.
- **Q-OPEN-226:** 일시정지 열기를 "세 손가락 길게 500ms / 상태바 시각 1.5초 / Esc"로 정했다. 모바일 브라우저의 세 손가락 제스처와 충돌할 수 있다([SYSTEM_SHELL_SPECIFICATION.md](../03-features/SYSTEM_SHELL_SPECIFICATION.md) Q-OPEN-102). 상태바 시각 길게를 항상 제공하는 것으로 확정할지 총괄 확인이 필요하다.
- **Q-OPEN-227:** 중앙 경고창을 **원격 지우기·암호 변경 두 곳만** 쓰고, 나머지 확인이 필요한 파괴적 동작은 확인 시트 1회로 정했다. [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md) 4.2는 기기 제거·예약 메일 삭제·사진 영구 삭제·차단·대화방 나가기·앱 데이터 삭제에도 중앙 경고창을 쓰도록 확장했다. 공통 지시서의 "2곳만"과 UI_UX의 확장 표가 충돌한다. 총괄이 하나로 확정해야 한다(추천: 공통 지시서대로 2곳만, 나머지는 확인 시트).
