# RESPONSIVE_DESIGN — 폭·높이·회전·플랫폼 대응

> **역할:** 화면이 320~430 폭, 짧은 높이, 데스크톱 프레임, 동적 글자, iPhone Safari에서 깨지지 않게 하는 단일 출처.
> **단일 출처:** 이 문서. 토큰 값은 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md), 그리드·레이아웃 원칙은 [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md)를 따른다.
> **참조:** [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) · [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md) · [ACCESSIBILITY.md](./ACCESSIBILITY.md) · [SCREEN_SPECIFICATIONS.md](./SCREEN_SPECIFICATIONS.md) · [FRONTEND_ARCHITECTURE.md](../04-tech/FRONTEND_ARCHITECTURE.md)
> **근거:** 공통 지시서 3.2(기준 390×844, 지원 320~430, 데스크톱 0.75~1.25), 원본 [SYSTEM_SHELL_SPECIFICATION](../03-features/SYSTEM_SHELL_SPECIFICATION.md)(모바일=전체 화면, 데스크톱=중앙 프레임).

## 1. 폭 대응

### 1.1 원칙

1. **레이아웃은 하나다.** 폭이 넓어져도 열을 추가하지 않는다. 390에서 정한 단일 열 구조를 유지하고, 사진·미디어만 커진다.
2. **좌우 여백은 16 고정.** 화면 폭이 변해도 `--lm-side`는 16이다. 전체 폭 예외(사진·지도·카메라·시네마틱)만 0이다.
3. **홈 아이콘은 60 고정.** 폭이 좁아지면 아이콘을 줄이지 않고 열 간격이 줄어든다. 간격 하한은 16이다.
4. **최소 폭 320.** 320 미만은 지원하지 않는다. 320 미만에서는 "화면이 너무 좁습니다" 안내를 띄우고 게임을 시작하지 않는다.
5. **최대 폭 430.** 모바일에서 430을 넘는 폭은 430으로 중앙 정렬하지 않고, 폰 프레임 규칙(5절)으로 전환한다.
6. **가로 스크롤 금지.** `body { overflow-x: hidden }`에 의존하지 않는다. 넘치는 원인을 없앤다. 긴 URL·파일명은 `overflow-wrap: anywhere`, 한국어 문장은 `word-break: keep-all`.

### 1.2 폭별 계산표

기준: 좌우 16, 홈 아이콘 4×60, 사진 그리드 3열·간격 2.

| 폭 | 콘텐츠 폭 | 홈 열 간격 | 사진 셀 | 판정 |
|---|---|---|---|---|
| 320 | 288 | 16 | 105.33 | 최소 지원. 모든 화면 검수 필수 |
| 360 | 328 | 29.33 | 118.67 | 안드로이드 소형 |
| 375 | 343 | 34.33 | 123.67 | iPhone SE2/3, 8 |
| 390 | 358 | 39.33 | 128.67 | **기준 프레임** |
| 414 | 382 | 47.33 | 136.67 | iPhone XR/11 |
| 430 | 398 | 52.67 | 142 | iPhone 14 Pro Max |

- 홈 열 간격 = `(100vw − 32 − 240) / 3`. 320에서 16, 430에서 52.67.
- 사진 셀 = `(100vw − 4) / 3`. 그리드는 좌우 0, 간격 2.
- 리스트·카드·시트는 폭에 비례해 늘어난다. 별도 max-width를 두지 않는다.

### 1.3 폭별 조정

| 폭 | 조정 |
|---|---|
| 320~359 | 버튼은 최대 2개까지 가로 배치. 3개 이상은 세로. 내비 제목은 최대 12자, 넘으면 말줄임. 시트 좌우 16 |
| 360~389 | 기본. 내비 제목 최대 16자 |
| 390~430 | 기본. 여백이 늘어난 만큼 사진·미디어가 커진다. 텍스트 줄 길이는 `max-width: 360px`로 제한(메일·메모 본문) |
| 431 이상(모바일 아님) | 5절 데스크톱 프레임으로 전환 |

## 2. 높이 대응

### 2.1 기준

- 기준 높이 844. 지원 높이 568~932.
- 콘텐츠는 항상 세로 스크롤이다. 크롬(상태바·내비·탭)은 고정, 본문만 스크롤한다.
- 높이가 줄면 **행 수를 줄이거나 스크롤**한다. 글자 크기·터치 영역을 줄이지 않는다.

### 2.2 짧은 높이(667)

- 667×375(iPhone SE2/3)을 기준으로 검수한다.
- 상태바는 실제 `env(safe-area-inset-top)`을 쓴다. 노치가 없으면 20, 있으면 44~47이다.
- 콘텐츠 영역 = `100dvh − 상태바 − 내비 − 탭바 − 안전영역`. 667에서 탭 바가 있으면 약 574가 남는다.
- **홈 행 수:** 모든 높이에서 5행(캐논 4×5). 5×82 + 4×18 = 482.
  - 5행 + 크롬(47+12+482+16+84+21) = 662로 667 안에 들어간다. 667에서는 위젯 줄을 숨기고 격자만 보인다(위젯은 오른쪽으로 밀어 여는 오늘 보기에서 본다). 실제 안전영역이 20이면 더 여유가 있다.
- **시트:** 최대 높이 `min(90dvh, 100dvh − 48px)`. 내용이 넘치면 시트 안에서 스크롤. 하단 버튼은 시트 하단에 고정.
- **경고창:** 최대 높이 80dvh. 본문이 넘치면 본문만 스크롤. 버튼은 항상 보인다.
- **작성창:** 키보드가 열리면 `visualViewport.height` 기준으로 목록을 줄이고, 입력창을 키보드 위 16에 고정한다. 667에서는 메시지 목록이 1~2행만 보여도 정상이다.
- **사진 확대:** 전체 화면 모달. 상단 내비 44, 하단 정보 0. 이미지는 남은 높이에 맞춘다.
- **설정 목록:** 행 수가 많으므로 스크롤. 섹션 스티키 헤더는 높이 32.

### 2.3 아주 짧은 높이(568~666)

- 홈은 5행 유지. 독 높이 76, 상단 여백 8, 행 간격 10.
- 상태바·내비·탭바는 줄이지 않는다. 대신 콘텐츠 상단 여백을 8로 줄인다.
- 큰 제목(large-title)은 스크롤과 동시에 `headline`으로 즉시 축소한다.
- 가로 모드로 판단되는 높이(≤500)는 3절 회전 안내를 우선한다.

## 3. 가로 모드

### 3.1 지원하지 않는다

- 이 게임은 **세로 고정**이다. 가로 모드에서 앱 화면을 억지로 재배치하지 않는다.
- 모바일 브라우저는 방향 잠금을 강제할 수 없으므로, 가로로 돌아가면 **회전 안내 화면**을 덮는다.
- 판정: `(orientation: landscape) and (pointer: coarse) and (max-height: 500px)`.
- 데스크톱은 화면이 가로여도 폰 프레임이 세로이므로 해당 없음(5절).

### 3.2 회전 안내 화면 명세

| 항목 | 값 |
|---|---|
| 배경 | `--lm-bg`(다크) 또는 라이트 배경. 뒤 앱은 보이지 않게 완전히 덮는다 |
| 아이콘 | 28pt 모노라인, 폰이 세로로 서 있는 모양 + 회전 화살표. `label-2` |
| 제목 | `title-2` "세로로 돌려 주세요" |
| 본문 | `subhead`, `label-2` "이 게임은 세로 화면에서만 플레이할 수 있습니다." |
| 정렬 | 화면 중앙, 좌우 32 |
| 동작 | 없음. 회전하면 자동으로 사라진다 |
| 상태 | 회전 중에도 게임 상태·타이머·오디오를 멈추지 않는다. 안내는 시각적 덮개일 뿐이다 |
| 접근성 | `role="dialog"`, `aria-modal="true"`, `aria-live="polite"`. 포커스는 안내로 이동, 회전 해제 시 원래 요소로 복귀 |

- 안내 화면에 게임 정보·시간·알림을 표시하지 않는다.
- "가로 모드를 지원하지 않습니다" 같은 기술 문구 대신 위 문구를 쓴다.

## 4. 데스크톱 폰 프레임

### 4.1 판정

- `(pointer: fine)`이고 뷰포트 폭 768 이상이면 데스크톱 모드다.
- 모바일·태블릿(거친 포인터)은 전체 화면 모드다.

### 4.2 프레임

| 항목 | 값 |
|---|---|
| 프레임 | 390×844 고정. 내부 레이아웃은 모바일과 완전히 같다 |
| 배치 | 화면 중앙. 가로·세로 중앙 |
| 스케일 | `clamp(0.75, min((뷰포트 높이 − 48) / 844, (뷰포트 폭 − 96) / 390), 1.25)` |
| 변환 | `transform: scale()` + `transform-origin: center`. 레이아웃 박스는 390×844 그대로 |
| 최소 | 0.75. 0.75에서도 높이가 넘치면 페이지 세로 스크롤을 허용하고 프레임 상단을 24에 맞춘다 |
| 최대 | 1.25. 그 이상 확대하지 않는다 |
| 모서리 | 프레임 바깥 모서리 40(기기 베젤), 화면 모서리 0 |
| 그림자 | 책상 위에 놓인 느낌의 부드러운 그림자. **연출이며 단서가 아니다** |
| 배경 | 도현의 방 책상. 나뭇결, 스탠드 불빛(2700K), 충전 케이블. 정지 이미지 |
| 정보 | 배경에 글자·단서·사물 라벨·상호작용 없음. 클릭해도 아무 일도 일어나지 않는다 |

- 스케일 계산 예: 1080 높이 → (1080−48)/844 = 1.223. 900 높이 → 1.009. 700 높이 → 0.773.
- 창 크기가 바뀌면 스케일만 다시 계산한다. 게임 상태·스크롤을 초기화하지 않는다.
- 프레임 밖 클릭·휠은 게임에 전달하지 않는다. 프레임 안의 스크롤만 게임 스크롤이다.
- 데스크톱에서도 폰 안의 가상 키보드를 그대로 보여 준다. 물리 키보드 입력도 같은 입력 필드에 들어간다. OS 키보드는 뜨지 않는다.
- 호버는 보조 피드백이다. 호버에만 있는 정보를 만들지 않는다. 포커스 링은 [ACCESSIBILITY.md](./ACCESSIBILITY.md) 3절.

### 4.3 배경 이미지 규칙

- 도현의 방 책상은 **정보가 없는 배경**이다. 봉투·포스트잇·서류를 배경에 두지 않는다.
- 카메라 앱의 도현의 방(4구도)과 혼동되지 않게, 데스크톱 배경은 초점이 흐린 저조도로 처리한다.
- 배경에 움직임·패럴랙스·호버 효과를 넣지 않는다.
- 배경 이미지가 없거나 로드되지 않으면 단색 `#1A1512`를 쓴다. 레이아웃은 변하지 않는다.

## 5. 동적 글자 4단계

### 5.1 단계

| 단계 | 배율 | 사용자 표기 | 검수 |
|---|---|---|---|
| xs | 0.85 | 작게 | 320 폭에서 정보 손실 없음 |
| md | 1.0 | 기본 | 기준 |
| lg | 1.15 | 크게 | 모든 화면 |
| xl | 1.3 | 아주 크게 | 모든 화면. 320 폭 필수 |

- 적용은 루트의 `data-text-size`와 `--lm-type-scale`로 한다. 브라우저 확대·축소에 의존하지 않는다.
- `text-size-adjust: 100%`로 iOS의 자동 글자 확대를 끄고, 게임 배율만 적용한다.

### 5.2 깨지지 않는 규칙

| 요소 | 규칙 |
|---|---|
| 행 높이 | `height`가 아니라 `min-height`를 쓴다. 행은 내용만큼 늘어난다. 1줄 행이 3줄이 되어도 잘리지 않는다 |
| 목록 행 | 주 텍스트는 최대 3줄, 보조 텍스트는 최대 2줄. 넘으면 말줄임. **주 정보는 말줄임하지 않는다** |
| 말줄임 | 보조·메타데이터에만 `text-overflow: ellipsis`. 주 텍스트·버튼 라벨·경고 문구에는 쓰지 않는다 |
| 줄바꿈 | 한국어 `word-break: keep-all`, 긴 URL·파일명 `overflow-wrap: anywhere`. `hyphens`는 쓰지 않는다 |
| 버튼 | 최소 높이 44, 내용만큼 세로로 늘어난다. 라벨 최대 2줄. 가로 패딩 16 고정 |
| 내비 | 일반 내비 44는 최소값. 제목이 넘치면 말줄임. 큰 제목은 2줄까지 허용하고 내비 높이가 자동으로 늘어난다(96 이상) |
| 탭 바 | 높이 49 유지. 라벨은 `caption-1` 12→15.6(xl)까지. 2줄 금지, 1줄 말줄임 |
| 잠금 시계 | `display-clock` 76→98.8(xl). 5자(`21:10`)가 320 폭에 들어가는지 검수. 들어가지 않으면 시계만 `clamp(64px, 19.5vw, 98.8px)`로 줄인다 |
| 시트 | 내용 스크롤. 제목·버튼은 고정. 버튼 라벨 2줄 허용 |
| 작성창 | 입력창은 최대 5줄까지 늘어나고, 넘으면 입력창 안에서 스크롤. 키보드 위 16 유지 |
| 사진 캡션 | 2줄까지. 그리드 라벨은 1줄 말줄임(장식이므로 허용) |
| 표 | 표를 쓰지 않는다. 라벨-값 2열은 값이 길면 다음 줄로 접는다. 가로 스크롤 표 금지 |
| 경고창 | 제목 2줄, 본문 4줄까지. 넘으면 본문 스크롤. 버튼은 항상 보인다 |
| 토스트 | 최대 2줄, 3초. 넘으면 말줄임(비핵심) |

### 5.3 검수 조합

- 320 × xs/md/lg/xl × 라이트/다크.
- 390 × xl × 라이트/다크.
- 430 × xl.
- 667 높이 × xl: 작성창·시트·경고창.
- 1.3배에서 가로 스크롤이 생기면 실패다.

## 6. iPhone Safari 대응

### 6.1 뷰포트

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

- `viewport-fit=cover`로 노치 영역까지 배경을 칠한다. 콘텐츠는 `env(safe-area-inset-*)` 안에 둔다.
- 높이는 `100dvh`를 기본으로, 미지원이면 `100vh` 폴백. `dvh`는 주소창이 접히고 펴질 때 실제 보이는 높이를 따른다.
- `position: fixed` 크롬은 `top: env(safe-area-inset-top)` / `bottom: env(safe-area-inset-bottom)`을 쓴다.
- `100vh` 고정 높이로 레이아웃을 만들지 않는다. 주소창 변화 때 콘텐츠가 잘린다.

### 6.2 안전영역

| 영역 | 처리 |
|---|---|
| 상단 노치·다이내믹 아일랜드 | 상태바는 `safe-top + 44`. 콘텐츠를 safe-top 위로 올리지 않는다 |
| 하단 홈 인디케이터 | 탭 바 아래 `max(34, safe-bottom)`. 홈 인디케이터 위 8 |
| 좌우(가로 모드) | 가로 모드를 지원하지 않으므로 해당 없음. 회전 안내가 덮는다 |
| 키보드 | `visualViewport`의 `height`·`offsetTop`을 구독해 입력창을 키보드 위로 올린다 |

- 안전영역이 0인 기기(홈 버튼)에서는 기본 34 대신 0을 쓴다. 빈 공간을 만들지 않는다.
- 유리 재질 크롬은 안전영역까지 확장하고, 내용만 안쪽에 둔다.

### 6.3 주소창·툴바

- Safari 하단 툴바가 보이면 `dvh`가 줄어든다. 탭 바는 줄어든 높이 안에서 함께 올라온다. 별도 보정값을 더하지 않는다.
- 스크롤로 주소창이 접히면 `dvh`가 커진다. 크롬 위치가 튀지 않게 `transform`이 아니라 `bottom` 고정을 쓴다.
- 풀투리프레시를 막는다: `body { overscroll-behavior-y: contain }`. 홈에서 아래로 끌기는 알림 센터다.
- 당겨서 새로고침이 발생해도 게임은 자동 저장에서 복구된다. 그래도 발생하지 않게 한다.

### 6.4 제스처 충돌

| 충돌 | 대응 |
|---|---|
| 왼쪽 가장자리 스와이프 = Safari 뒤로 | **게임 내 뒤로 버튼을 항상 병행**한다. 제스처만 요구하지 않는다. 자동 저장으로 상태 손실을 막는다 |
| 두 손가락 확대 = Safari 페이지 확대 | 사진·지도 확대 영역은 `touch-action: none`과 자체 핀치를 쓰고, **확대/축소 버튼을 대체 제공**한다. 페이지 전체 확대는 막지 않는다(접근성) |
| 두 번 탭 = Safari 확대 | 버튼·카드에는 `touch-action: manipulation`. 사진 두 번 탭 좋아요는 사진 영역에서만, 300ms 안에 두 번 |
| 길게 누르기 = 텍스트 선택·콜아웃 | 크롬에는 `-webkit-touch-callout: none`, `user-select: none`. 메시지·메일 본문은 선택·복사 허용. 맥락 메뉴는 500ms 타이머 + `contextmenu` 차단 |
| 홈 인디케이터 위로 = 홈 | 탭 바·하단 버튼을 인디케이터에서 34 이상 띄운다. 하단 8px 안에 터치 대상 금지 |
| 뒤로 제스처 중 스크롤 | 스크롤 컨테이너 `overscroll-behavior-x: none`. 가로 캐러셀은 가장자리에서 저항(rubber band) |
| 화면 회전 | 3절 회전 안내 |

- **원칙:** 브라우저 제스처를 이길 수 없다고 가정한다. 게임의 핵심 동작은 항상 버튼으로도 가능해야 한다. 이것은 접근성 요구이기도 하다.

### 6.5 저장·복구

- Safari가 탭을 메모리에서 내려도 `localStorage` 자동 저장에서 복구한다.
- 복구 시 마지막 화면·스크롤·입력 중이던 초안(작성창)을 복원한다. 입력 중 초안은 10초마다 임시 저장한다.
- 복구 화면을 따로 만들지 않는다. 같은 화면으로 바로 돌아온다.

## 확인 사항

- (해결) 홈은 모든 높이에서 4×5.
- `Q-OPEN-06`: 데스크톱 배경을 "도현의 방 책상"으로 확정했지만, 배경 이미지 제작은 P5(아트)다. 그전에는 단색 폴백을 쓴다. 배경 이미지에 스탠드·케이블 외의 사물을 넣지 않는 규칙은 이 문서가 단일 출처다.
- `Q-OPEN-07`: iOS Safari의 왼쪽 가장자리 뒤로 제스처는 게임이 완전히 막을 수 없다. 자동 저장으로 손실은 막지만, 제스처 자체를 비활성화할 방법은 없다. 게임 내 뒤로 버튼 병행으로 확정한다.
