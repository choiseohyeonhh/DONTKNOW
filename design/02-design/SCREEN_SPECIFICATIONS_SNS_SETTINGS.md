# SCREEN_SPECIFICATIONS_SNS_SETTINGS — 루프·설정 화면 명세

> **역할:** 루프(SNS)와 설정 앱의 P0 화면을 14항목 전부로 상세화하고, P1 화면을 압축 표로 확정한다. 구현자가 판단 없이 레이아웃·상태·전환·데이터 표시를 따라 할 수 있게 한다.
> **단일 출처:** 이 문서 = 루프·설정 화면의 **레이아웃 수치·영역별 y좌표·표시 데이터·화면별 상태**. 화면 ID는 [NAVIGATION_ARCHITECTURE.md](./NAVIGATION_ARCHITECTURE.md) 3.3·4절 확정본만 쓴다. 토큰 값은 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md), 컴포넌트 구조는 [COMPONENT_SPECIFICATIONS.md](./COMPONENT_SPECIFICATIONS.md), 마이크로 인터랙션은 [INTERACTION_SPECIFICATIONS.md](./INTERACTION_SPECIFICATIONS.md)가 단일 출처다. 기능·데이터 원본은 [SNS_SPECIFICATION.md](../03-features/SNS_SPECIFICATION.md), [SETTINGS_SPECIFICATION.md](../03-features/SETTINGS_SPECIFICATION.md)다.
> **참조:** [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) · [UI_UX_GUIDELINES.md](./UI_UX_GUIDELINES.md) · [RESPONSIVE_DESIGN.md](./RESPONSIVE_DESIGN.md) · [ACCESSIBILITY.md](./ACCESSIBILITY.md) · [ICONOGRAPHY_AND_IMAGERY.md](./ICONOGRAPHY_AND_IMAGERY.md) · [CHARACTERS.md](../01-product/CHARACTERS.md) · [EVIDENCE_LEDGER.md](../01-product/EVIDENCE_LEDGER.md) · [NARRATIVE_CANON.md](../01-product/NARRATIVE_CANON.md) · [TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md).
> **근거:** 공통 지시서 3.2·3.3·3.4, SCREEN_BRIEF, NAVIGATION_ARCHITECTURE 3.3(루프 23)·3.10(설정 29)·4절. 캐논 숫자·시각·ID·계정·문구는 원본 그대로 옮겼다.
> **범위:** 루프 23화면 전부(P0 9 + P1 14), 설정은 요청된 9개 영역(P0 6 + P1 3)과 검색 1 + 하위 시트 2 + 시러스 가족 1. 설정의 나머지 메뉴는 [SETTINGS_SPECIFICATION.md](../03-features/SETTINGS_SPECIFICATION.md)와 NAVIGATION_ARCHITECTURE가 정의한다.
> **P0/P1:** P0는 14항목 전부를 쓴다. P1은 화면당 표 한 개(14항목을 행으로)로, 공통 패턴과 같으면 "공통 패턴명 따름"으로 적고 다른 점만 쓴다.

### 0.2 화면 작성 공통 규칙

1. 한 화면에 `h1`은 하나다. 큰 제목과 탭 바를 같은 화면에 동시에 쓰지 않는다(앱 루트는 하나만).
2. 앱 강조색은 루프 `--lm-app-tint`(라이트 `#B55FA4`, 다크 `#D29EC7`) 하나만 쓴다.
3. 모든 수치는 [DESIGN_TOKENS.md](./DESIGN_TOKENS.md)와 [COMPONENT_SPECIFICATIONS.md](./COMPONENT_SPECIFICATIONS.md) 값만 쓴다. 새 값이 필요하면 이유를 적고 5절 확인 사항에 올린다.
4. 정보(i)·메타데이터는 **열어야 보인다.** 목록 행에 촬영·위치·읽음·편집 시각을 미리 요약하지 않는다.
5. 정답·오답·진행도·"새 정보" 배지·근거 강조를 만들지 않는다. 화면은 사실만 표시한다.
6. 흔적(읽음·조회·좋아요·캡처)을 시스템이 설명하지 않는다. 동기화 점의 의미도 설명하지 않는다.
7. 실제 서비스명·로고를 화면 문구·아이콘에 쓰지 않는다. 앱 이름은 "루프", "시러스 ID"만 쓴다.
8. 게시물 시각은 절대 시각 `YYYY.MM.DD`(목록·상세), 대화·알림은 `M/D HH:MM`을 쓴다. 숫자는 `tabular-nums`.
9. 오프라인·삭제·잠김·원격 삭제 중 상태를 화면마다 명시한다.
10. `prefers-reduced-motion` 또는 게임 설정 "동작 줄이기"면 모든 이동을 150ms 페이드 또는 즉시 상태 변화로 바꾼다.
11. 말줄임: 주 정보(이름·본문·버튼 라벨·경고 문구)는 말줄임하지 않는다. 보조·메타데이터만 1줄 말줄임하고, 목록 행은 주 텍스트 최대 2줄·보조 최대 1줄이다.

### 1.3 이 문서가 올리는 확인 사항(요약)

- `Q-OPEN-301`: 인용 작성에 독립 SCR ID가 없다. `SCR-LOOP-CREATE`의 `mode="quote"` 변형으로 확정했다. 인벤토리에 별도 인용 화면 ID를 추가할지 총괄 확인이 필요하다.
- `Q-OPEN-302`: 게시물 시각 표기. SNS 8.10은 피드에서 상대 시각("3일 전"), 정보에서 절대 시각이라 하고, UI_UX 2.5는 게시물을 전부 절대 시각이라 한다. 이 문서는 UI_UX를 따라 게시물 카드·상세에 `YYYY.MM.DD`를 쓴다. 한쪽으로 확정이 필요하다.
- `Q-OPEN-303`: 차단된 계정의 프로필을 "차단 목록에서 다시 열기"로 볼 때의 화면 상태. 이 문서는 `SCR-LOOP-PROFILE`의 `blocked=true` 상태(게시물·스토리·하이라이트 숨김, 차단 해제 버튼만)로 정의했다. 웨이브 로그아웃 열람은 루프 밖이므로 다루지 않는다.
- `Q-OPEN-304`: 설정 루트 검색창은 `SCR-SET-SEARCH`로 push한다. 검색 결과를 루트 인라인으로 둘지 push로 둘지 인벤토리는 push로 확정했다. 이 문서는 push를 따른다.

## 2. P0 상세 명세 (14항목)

## 2.1 SCR-LOOP-FEED — 홈 피드

**1. 목적.** 팔로잉·추천 게시물을 시간순으로 훑고, 스토리·DM·게시물 상세로 들어가는 루프의 시작 화면이다. 사진 게시물과 글 게시물이 같은 피드에 섞인다.

**2. 진입 경로.** 홈 → 루프 아이콘. 하단 탭 `홈` 재탭 = 맨 위로. 알림의 루프 활동 탭은 게시물 상세로 딥링크하고, 피드는 그 아래 스택에 남는다.

**3. 전체 레이아웃.**

```text
y=0    ┌──────────────────────────────────────┐
       │ 상태바 47                             │ 47
y=47   ├──────────────────────────────────────┤
       │ 루프                            ⌕  DM │ 44
y=91   ├──────────────────────────────────────┤
       │ 스토리 트레이 (아바타 56 + 이름 16)     │ 72
y=163  ├──────────────────────────────────────┤
       │ (8)                                   │
y=171  ├──────────────────────────────────────┤
       │ [ 팔로잉 ][ 추천 ]  세그먼트 32         │ 32
y=203  ├──────────────────────────────────────┤
       │ (8)                                   │
y=211  ├──────────────────────────────────────┤
       │ 사진 게시물 카드                       │
       │  헤더 56                               │
       │  미디어 390×487.5 (4:5)                │
       │  액션 바 44                            │
       │  캡션·메타 60                          │
       │ ── 16 ──                               │
       │ 글 게시물 카드                         │
       │  헤더 56 / 본문 / 사진 2×2 / 액션 44   │
       │  …                                     │
y=761  ├──────────────────────────────────────┤
       │ 탭 바 49                               │ 49
y=810  ├──────────────────────────────────────┤
       │ 안전영역 34 (홈 인디케이터 134×5)       │ 34
y=844  └──────────────────────────────────────┘
```

|---|---|---|---|
| 상태바 | 0 | 47 | `CMP-STATUS-BAR` (시각·서비스 없음·Wi-Fi·동기화 점·배터리) |
| 내비 | 47 | 44 | "루프" `headline`, 우측 검색·DM 아이콘 44 |

| 세그먼트 | 171 | 32 | `CMP-SEGMENTED` 2분할 |
| 간격 | 203 | 8 | — |
| 피드 | 211 | 550 | `CMP-POST-CARD-PHOTO`·`CMP-POST-CARD-TEXT` 세로 스크롤 |

**11. 로딩·빈 화면.**
- 첫 온라인 직후 캐시 피드를 먼저 그리고 상단에 진행 표시. 200ms 넘으면 `CMP-SKELETON` 카드 1장(미디어 포함), 3초 넘으면 "불러오는 중…".
- 팔로잉 0건: `CMP-EMPTY-STATE` 제목 "게시물이 없습니다", 본문 없음, 행동 없음. 추천 계정·광고를 끼워 넣지 않는다.
- 추천 0건: 제목 "추천할 게시물이 없습니다", 본문 없음.

**12. 오류·예외.**
- 오프라인: 캐시 피드만. 상단 `CMP-INLINE-NOTICE` "오프라인 저장본 · 3/15 03:58 기준". 검색·스토리·DM·활동 상태 불가. 좋아요·조회·읽음은 대기.
- 삭제됨: 다른 기기에서 삭제된 게시물 행은 0.4초 페이드 후 사라지고 "1개 항목이 다른 기기에서 삭제됨" 3초. 게시물 자체 삭제는 캐논에 없다.
- 잠김: 비공개 계정(A-12) 게시물은 피드에 나오지 않는다. 차단 계정도 나오지 않는다.
- 원격 삭제 중: 피드를 조작할 수 없다. `SCR-OS-LOCK` 상태가 덮고 일시정지 메뉴만 열린다.

**13. 반응형.**
- 320: 스토리 항목 72 유지, 카드 미디어 320×400, 세그먼트 라벨 말줄임 없음. 430: 미디어 430×537.5, 여백 그대로.
- 667 높이: 콘텐츠 91~584(탭 바 584~667). 카드 1장이 일부만 보여도 정상. 위젯 없음.
- 글자 4단계: 카드 캡션은 최대 3줄, 사용자명 1줄 말줄임. `caption-2` 11 하한. xl에서도 카드 미디어 비율 유지.

**14. 접근성.**
- 역할: 피드 `list`, 카드 `article` + `aria-labelledby`(작성자·본문 요약), 사진 `img` + `alt`, 좋아요 `aria-pressed`, 세그먼트 `tablist/tab` + `aria-selected`.
- 포커스 순서: 내비 → 스토리 → 세그먼트 → 카드 1 → … → 탭 바. 카드 안에서는 작성자 → 미디어 → 좋아요 → 댓글 → 공유 → 저장.
- 대체 조작: 두 번 탭 좋아요 = 좋아요 버튼, 캐러셀 = 이전/다음 44 버튼, 당겨서 새로고침 = 내비의 "새로고침" 텍스트 버튼(온라인일 때), 스토리 = 탭/버튼.
- 스크린리더: "{계정 이름}, {게시 날짜}, 사진 {n}장, 좋아요 {n}개". 동기화 점은 "동기화 표시"만.

| 카메라 아이콘 | 사진 앱 선택 시트 → "같은 사진" / "같은 장소일 수 있음" 결과 | 사진으로 찾기 사용은 활동 기록에 남음(EV-32 넛지) |

| 그리드 셀 탭 | 해당 게시물 상세 push | — |
| 당겨서 새로고침 | 온라인: 그리드·트렌드 갱신 | — |

**9. 화면 전환.** 검색 = `SCR-LOOP-SEARCH` push / 트렌드 = `SCR-LOOP-TAG`·`SCR-LOOP-PLACE` push / 셀 = `SCR-LOOP-POST-PHOTO` push / 사진으로 찾기 결과 = `SCR-LOOP-SEARCH`의 결과 상태 / 오프라인 = 인라인 안내가 있는 같은 화면.

**10. 데이터 표시.**
- 검색창 플레이스홀더 "검색". 계정·태그·장소를 검색한다. **이전 사용자 이름으로는 검색되지 않는다.**
- 트렌드 5행: "지금 성원에서", 순번 1~5, 태그, "게시물 N". 장식이며 캐논 근거를 새로 만들지 않는다.
- 그리드: 공개 사진 게시물. 차단 계정·비공개 계정 게시물은 나오지 않는다. 정렬 = 최신·인기 혼합(그리드 순서는 장식).
- 로딩: 캐시 그리드를 먼저, 200ms 후 스켈레톤.
- 빈 화면: "표시할 사진이 없습니다", 행동 없음. 추천 계정을 넣지 않는다.

**11. 로딩·빈 화면.** 200ms 넘으면 그리드 셀 스켈레톤. 트렌드 0건이면 트렌드 섹션을 표시하지 않는다. 검색 0건은 `SCR-LOOP-SEARCH`에서 "결과 없음".

**12. 오류·예외.** 오프라인: 캐시 그리드만 + `CMP-INLINE-NOTICE` "오프라인 저장본 · 3/15 03:58 기준". 검색·사진으로 찾기 불가("온라인이 필요합니다."). 차단 계정은 그리드에서 숨김. 만료 스토리는 트렌드·그리드에 없다. 원격 삭제 중: `SCR-OS-LOCK` 상태가 덮고 입력을 받지 않는다.

**13. 반응형.** 320: 그리드 셀 105.33, 검색 필드 폭 288. 430: 셀 142. 667 높이: 콘텐츠 91~584, 트렌드 5행 + 그리드 1.5행. 글자 xl: 트렌드 행 높이 `min-height`로 늘어남, 태그 1줄 말줄임.

**14. 접근성.** 검색 `search`+`searchbox` `aria-label="검색"`, 카메라 `aria-label="사진으로 찾기"`, 트렌드 행 `button` + "1위 성원대교", 그리드 `list` + 셀 `button` + `alt`. 포커스: 내비 → 검색 → 트렌드 1~5 → 그리드 → 탭. 가로 스크롤 없음.

       │        [위치 스티커]                  │
       │                                      │
       │  ← 탭 30%              탭 70% →      │
y=792  ├──────────────────────────────────────┤
       │ 답장 입력…                     👁 N   │ 52

| 영역 | y | 높이 | 내용 |
|---|---|---|---|
| 진행 막대 | 8 | 3 | 세그먼트(스토리 수), 간격 4, `label` |

## 2.9 SCR-LOOP-DM-ROOM — DM 대화

**1. 목적.** 1:1 DM 대화를 읽고 답장한다. 읽음 확인, 보내지 않은 초안, 공유 게시물 원본 열기를 한 화면에서 다룬다.

**3. 전체 레이아웃.**

**9. 화면 전환.** 검색 = `SCR-SET-SEARCH` push / 시러스 ID = `SCR-SET-CIRRUS` push / Wi-Fi = `SCR-SET-WIFI` push / 알림 = `SCR-SET-NOTIFICATIONS` push / 집중 모드 = `SCR-SET-FOCUS` push / 디스플레이 = `SCR-SET-DISPLAY` push / 나머지 행 = 각 `SCR-SET-*` push.

| 스크린 타임(기기 간 공유) | 켜짐 | 슬레이트 사용 시간 안 보임 |

**13. 반응형.** 320: 행 60 유지, 보조 문구 2줄. 430: 여백 증가. 667 높이: 목록 스크롤, 스위치 고정. 글자 xl: 보조 문구 2줄, 주 텍스트 1줄.

**14. 접근성.** `switch` + `aria-checked`, 옆에 "켜짐/꺼짐" 텍스트. 각 행 `listitem` + `aria-label`(앱 이름, 상태). 포커스: 뒤로 → 사진 → 메모 → … → 스크린 타임. 스위치 터치 44.

## 3. P1 압축 명세

- 표의 행은 P0의 14항목과 같은 순서다. 공통 패턴과 같으면 "패턴 A 따름"처럼 적고, 다른 점만 쓴다.
- P1도 P0와 같은 토큰·컴포넌트·접근성 규칙을 따른다. 새 값은 만들지 않는다.
- P1 화면의 상태·문구는 P0와 동일한 원칙(정보(i)는 열어야 보임, 흔적 설명 없음, 정답 판정 없음)을 따른다.

## 6. 확인 사항

- **Q-OPEN-301:** 인용 작성에 독립 SCR ID가 없다. `SCR-LOOP-CREATE`의 `mode="quote"` 변형으로 확정했다. 인벤토리에 별도 인용 화면 ID를 추가할지 총괄 확인이 필요하다.
- **Q-OPEN-302:** 게시물 시각 표기. SNS 8.10은 피드에서 상대 시각("3일 전"), 정보에서 절대 시각이라 하고, UI_UX 2.5는 게시물을 전부 절대 시각이라 한다. 이 문서는 UI_UX를 따라 게시물 카드·상세에 `YYYY.MM.DD`를 썼다. 한쪽으로 확정이 필요하다.
- **Q-OPEN-303:** 차단된 계정의 프로필을 "차단 목록에서 다시 열기"로 볼 때의 화면 상태를 `SCR-LOOP-PROFILE`의 `blocked=true`(헤더 + "차단한 계정입니다" + `차단 해제`만)로 정의했다. 웨이브 로그아웃 열람은 루프 밖이므로 다루지 않는다.
- **Q-OPEN-304:** 설정 루트 검색창은 `SCR-SET-SEARCH`로 push한다. 검색 결과를 루트 인라인으로 둘지 push로 둘지 인벤토리는 push로 확정했다. 이 문서는 push를 따른다.
