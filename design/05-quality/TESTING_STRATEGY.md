# TESTING_STRATEGY — 린터·단위·경로·시각·접근성·실기기·플레이테스트

> **역할:** 콘텐츠 린터, 단위 테스트(시계·가시성·동기화·verify·trace), Playwright 경로 테스트(route_a, route_a2, route_b, route_c, route_d, crisis, traces, moved), 시각 회귀, 접근성 검사, iPhone 실기기 체크리스트, 플레이테스트 계획을 고정한다.
> **단일 출처:** 이 문서(테스트 전략·경로별 단계·합격 기준). 경로 테스트 목록의 원본은 [SYSTEM_ARCHITECTURE](../04-tech/SYSTEM_ARCHITECTURE.md) 6절, 성능 예산은 [PERFORMANCE_REQUIREMENTS](./PERFORMANCE_REQUIREMENTS.md), 린터 규칙은 [DATABASE_SCHEMA](../04-tech/DATABASE_SCHEMA.md) 5절이 단일 출처다.
> **참조:** [SYSTEM_ARCHITECTURE](../04-tech/SYSTEM_ARCHITECTURE.md), [ACTION_PROOF](../01-product/ACTION_PROOF.md), [PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 6절, [TRACES_AND_REACTIONS](../01-product/TRACES_AND_REACTIONS.md), [PRD 성공 지표](../01-product/PRD.md) 6절, [PLAYTIME_BUDGET](../01-product/PLAYTIME_BUDGET.md) 6절.
> **적용 버전:** v6.2 (2026-11). **새 테스트 프레임워크·외부 라이브러리를 도입하지 않는다.** Playwright는 이미 환경에 있다.

## 1. 테스트 피라미드

| 계층 | 도구 | 대상 | 실행 시점 |
|---|---|---|---|
| L0 콘텐츠 린터 | Python `lint_content.py` | 모든 JSON | 빌드 전·커밋 전 |
| L1 단위 | 브라우저 하네스 + Playwright | 순수 함수·상태 전이 | 모듈 변경 시 |
| L2 경로 | Playwright | 클릭·입력으로 엔딩 재현 | PR·릴리스 전 |
| L3 시각 회귀 | Playwright 스크린샷 | 390×844 다크/라이트 | 화면 변경 시 |
| L4 접근성 | 자체 DOM 검사 + 수동 | 터치·대비·라벨·포커스 | 화면 변경 시 |
| L5 실기기 | iPhone Safari | 제스처·키보드·성능 | P1부터 매 단계 |
| L6 플레이테스트 | 사람 | 재미·막힘·페이싱 | P7 |

- L0~L2는 자동화한다. L3~L4는 자동+수동. L5~L6은 수동이다.
- 테스트는 `?test=1`(또는 `?debug=1`)에서 `window.__game`을 쓴다([API_SPECIFICATION](../04-tech/API_SPECIFICATION.md) 6절).

## 2. L0 — 콘텐츠 린터

```text
python3 game/tools/lint_content.py --content game/content --strict
```

| 검사 | 합격 기준 |
|---|---|
| ID 참조 | 미정의 E/G/EV/V/TR/P/A/D/L/F 0 |
| 이중 경로 | 필수 V의 `basis`가 서로 다른 앱 2개 이상 |
| 소실 안전 | 필수 V의 근거가 원격 삭제 후에도 다른 앱 2개 이상 |
| 흔적 짝 | 모든 TR에 반응, 모든 반응 EV에 트리거 |
| 낱말 사전 | V 입력·유출 낱말 전부 등록 |
| 미끼 격리 | L-11 근거 전부 T2(E-130 예외) |
| 타임라인 | [NARRATIVE_CANON](../01-product/NARRATIVE_CANON.md) 연대기와 일치 |
| 이동 시간 | [LOCATIONS](../01-product/LOCATIONS.md) 이동 시간표 이상 |
| 앎 매트릭스 | NPC 응답에 금지 정보 없음 |
| 금칙어 | 수법 구체어 0 |
| 스키마·중복·조건식·층·엔딩·자산·생성 항목·금지 어휘 | L11~L18 전부 |

- `--strict`에서 경고도 실패다. 린터 실패 시 빌드하지 않는다.
- 린터는 콘텐츠를 수정하지 않는다.

## 3. L1 — 단위 테스트

### 3.1 실행 방식

- `game/tests/unit.html`을 Playwright로 연다. 이 페이지는 ES 모듈을 로드하고 순수 함수를 직접 호출한다.
- 새 테스트 러너 라이브러리를 추가하지 않는다. `assert` 함수와 `report()`만 쓴다.
- DOM이 필요한 테스트는 최소 DOM을 만든 뒤 `morph`만 검증한다.
- 시계·랜덤은 주입한다: `clock.setGameMin`, `seed(n)`, `now` 대체.

### 3.2 시계(`clock`)

| 케이스 | 기대 |
|---|---|
| ×4 누적 | 실시간 15초 = 게임 1분 |
| 710게임분 | 실시간 177분 30초 |
| "30분" | 30게임분 = 7분 30초 |
| 일시정지 메뉴 | `gameMin` 증가 없음 |
| 시네마틱 | 〃 |
| 백그라운드(`visibilitychange`) | 〃. 복귀해도 따라잡지 않음 |
| 시간 흐름 끄기 | 앱 전환 1회 = 1게임분, 자동 증가 없음 |
| 저장·복원 | 저장한 `gameMin`부터 재개 |
| 단조성 | 감소 없음(디버그 제외) |

## 6. L4 — 접근성 검사

### 6.1 자동 검사(자체 DOM)

| 검사 | 기준 |
|---|---|
| 터치 영역 | 모든 인터랙티브 요소 ≥ 44×44(히트 슬롭 포함) |
| 라벨 | 아이콘 버튼에 `aria-label`, 입력에 라벨 |
| 포커스 | 포커스 가능, 순서 논리적, 포커스 링 보임 |
| 시트 | `aria-modal`, 포커스 트랩, 닫기 |
| 대비 | 본문 4.5:1, 큰 글자 3:1 (라이트·다크) |
| 색 의존 | 상태를 색만으로 전달하지 않음 |
| 모션 | `prefers-reduced-motion` 시 이동 없음 |
| 확대 | 글자 1.3배에서 잘림·겹침 없음 |
| 이미지 | `alt` 존재(장식은 빈 alt) |

- **외부 `axe-core`를 추가하지 않는다.** 위 항목을 Playwright DOM 검사 + 수동으로 확인한다.
- 대비 계산은 토큰 값으로 미리 검증하고, 화면별 예외를 문서화한다.

### 6.2 수동 검사

- VoiceOver(iOS)로 잠금 해제 → 앱 열기 → 메시지 읽기 → 공유까지 1회.
- 키보드만으로(데스크톱) 잠금 화면 → 홈 → 앱 → 뒤로.
- 200% 브라우저 확대에서 가로 스크롤 없이 주요 화면 사용.

## 8. L6 — 플레이테스트

### 8.1 구성

| 대상 | 인원 | 조건 |
|---|---|---|
| 숙련자 | 2 | 추리 게임·스마트폰 숙련. 정답 미공개 |
| 일반 | 4 | 처음 하는 추리 게임 이용자. 정답 미공개 |

- 블라인드: 사전 설명은 "실종된 아들의 폰을 뒤지는 게임" 한 줄만.
- 진행자 개입: 막힘 20분 이상일 때만 "막혔을 때" 메뉴를 안내. 정답·경로는 말하지 않는다.
- 기록: 시작·종료 시각, 엔딩, 힌트 사용, 막힘 구간, 발화(반응 순간), 오류.

### 8.2 합격 기준

| 지표 | 목표 | 출처 |
|---|---|---|
| 숙련자 최솟값 | ≥ 90분 | [17](../01-product/PLAYTIME_BUDGET.md) 6절 |
| 일반 중앙값 | 140~190분 | 〃 |
| "내가 알아냈다" | 80%가 반전 3개 중 2개 이상 | [PRD](../01-product/PRD.md) 6절 |
| "진짜 폰을 뒤지는 느낌" | 70%가 기능 3개 이상 | 〃 |
| 반응 체감 | 80%가 "상대가 알아챈 순간" 1회 이상 | 〃 |
| 막힘 | 실시간 20분 이상 새 앱·행동 없음 < 10% | 〃 |
| 엔딩 분포 | A 20~30%, A′ 10~15%, B 10~20%, C 25~35%, D 10~20% | 〃 |

## 확인 사항

- `Q-OPEN-Q03`: 경로 테스트에서 시간 진행을 위해 `__game.advance()`를 쓰는 것은 [SYSTEM_ARCHITECTURE](../04-tech/SYSTEM_ARCHITECTURE.md) 6절 "클릭·입력만"과 문자적으로 충돌한다. 이 문서는 "상태 직접 주입 없이 시계만 진행"으로 해석했다. 총괄이 허용 범위를 확정해야 한다.
- `Q-OPEN-Q04`: 시각 회귀 기준 이미지를 저장소에 둘지, CI 아티팩트로만 둘지 결정이 필요하다. 이 문서는 저장소 보관을 가정했다.
- `Q-OPEN-Q05`: Playwright 설정 파일·실행 스크립트 이름은 구현 단계에서 정한다. `mvp/tests/` 구조를 그대로 쓰지 않는다.
- `Q-OPEN-Q06`: 실기기 테스트 기기 목록·OS 버전은 개발 환경에서 확정해야 한다.
