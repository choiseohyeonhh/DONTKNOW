# COMMERCE_AND_FINANCE_SPECIFICATION — 누리은행·한끼·이웃마켓·지갑 결제

> **역할:** 누리은행, 한끼(배달), 이웃마켓(중고거래), 지갑의 결제 부분을 구현 가능한 수준으로 정의한다. 돈의 흐름은 이 게임의 미드포인트다. 은행 거래내역이 "아버지의 빚"과 "아들의 돈"을 한 화면에서 만난다.

## 1. 누리은행

### 1.1 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: 토스, 은행 앱. 핵심 UX는 (a) 간편비밀번호/PIN 로그인, (b) 계좌 요약·잔액, (c) 거래내역(입금/출금, 기간·검색 필터), (d) 거래 상세(상대·메모·시각), (e) 내역 공유·캡처다.

### 1.2 ② 참고할 기능과 사용자 행동

- 간편비밀번호로 로그인한다.
- 계좌 잔액과 거래내역을 본다.
- 입금/출금·기간·검색으로 필터한다.
- 거래 상세를 열어 상대 계좌·메모를 본다.
- 거래 상세를 공유한다.

### 1.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 상대 계좌의 실명·메모를 상세 깊숙이 숨긴다. 개선: LUMA는 거래 상세에서 상대명·메모("가상계좌 / 채무자 이상철")를 바로 보여 준다.
- 레퍼런스는 필터가 여러 단계다. 개선: LUMA는 거래내역 상단에 입금/출금·기간·검색을 한 줄로 둔다(깊이 1단계).
- 레퍼런스는 보안 화면에서 입력 실수를 벌한다. 개선: LUMA는 간편비밀번호 오답에 계정 잠금을 두지 않는다(게임의 다른 자물쇠와 같은 원칙). 오답 시 재입력만.

### 1.4 ④ 이 게임에 적용하는 방식

- **온라인 필요.** 간편비밀번호 **110221**(엄마 기일 11/02 + 생일 끝자리 21). 출처: 잠긴 메모 "비번"(E-26) + 캘린더 "엄마"(E-17) + 응급정보 생년월일.
- 계좌 352-1048-7731, 잔액 15,212,400원(지급정지).
- 거래내역(필터: 입금/출금/기간/검색)에 캐논 5개 묶음이 있다. 상세에는 상대·메모가 있다.
- 거래 상세는 공유할 수 있다. 도현에게 보내면 빚 고백(V-13)의 근거가 된다.
- 은행 앱은 **T2 + T3**다. 온라인 전에는 열리지 않고, 온라인 후에도 110221을 입력해야 한다.
- 지급정지 상태라 출금·이체 기능은 없다. 잔액과 내역만 본다.
- 하린(박하린) 관련 반응은 은행 이후에 열린다. 반응은 [SNS_SPECIFICATION.md](SNS_SPECIFICATION.md)와 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md) 4.4가 단일 출처다.

## 2. 한끼 (배달)

### 2.1 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: 배달의민족. 핵심 UX는 (a) 가게·메뉴 탐색, (b) 장바구니·주문, (c) 배송지·요청사항, (d) 결제 수단, (e) 주문 내역·재주문, (f) 실시간 주문 알림이다.

### 2.2 ② 참고할 기능과 사용자 행동

- 주문 내역에서 과거 주문의 가게·메뉴·배송지·요청을 본다.
- 같은 주문을 재주문한다.
- 배송지를 바꾼다.

### 2.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 과거 배송지가 여러 개일 때 어느 주문이 어디로 갔는지 흐릿하다. 개선: LUMA는 주문 내역 행에 **배송지 전체 주소**를 표시하고, 주소가 바뀐 시점을 굵게 구분한다.
- 레퍼런스는 재주문 시 배송지를 확인 없이 이전 값으로 채운다. 개선: LUMA는 재주문 확인 시트에서 배송지를 크게 보여 주고, "이 주소로 갑니다"를 확정받는다. 이 확인이 곧 플레이어의 위험한 선택이다.
- 레퍼런스는 결제 수단이 없으면 주문을 막는다. 개선: LUMA는 "만나서 현금 결제"를 선택지로 제공한다(캐논).

### 2.4 ④ 이 게임에 적용하는 방식

- 다중기기 계정. 주문 내역(E-150, 온라인, 주문 기기 "슬레이트"): 3건 모두 배송지 **성원구청로 31, 해담고시텔 207호**, 요청 "문 앞에 두고 노크하지 마세요".
- 결제: 전부 "만나서 현금 결제"(계좌·카드가 정지됐다).
- 그 이전 주문(1~3월): 배송지 "성원아파트 103동"(집). 3/15부터 바뀐다.
- **게임 중(EV-26):** 3/18 07:10 "주문 접수" 알림(삼각김밥 2, 같은 배송지). 온라인일 때만.
- **재주문 버튼(EV-27):** 플레이어가 누를 수 있다. 해담 207호로 음식이 간다. 도현의 반응은 DH 상태에 따라 다르다. 아들에게 "어디 있는지 안다"고 말하는 가장 조용한 방법이자, 가장 위험한 방법.
- 재주문은 TR-17 흔적을 남긴다. DH≥3이면 "…아빠지. 거기까지 알아?" / DH≤2면 "누구야" + 경계 +2 + F-MOVED 판정.
- 재주문 확인 시트는 "배송지: 성원구청로 31, 해담고시텔 207호 / 문 앞에 두고 노크하지 마세요"를 그대로 보여 준다.
- 한끼는 **위치의 호실 단위 출처**다(E-150). 지도·찾기와 교차한다.

## 3. 이웃마켓 (중고거래)

### 3.1 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: 당근마켓. 핵심 UX는 (a) 동네 기반 판매 글 목록, (b) 판매 글(사진·가격·설명·상태), (c) 1:1 채팅, (d) 거래 상태(판매 중·예약 중·판매 완료), (e) 약속 장소·시간 조율이다.

### 3.2 ② 참고할 기능과 사용자 행동

- 판매 글 목록과 글 상세를 본다.
- 판매 상태(판매 중/예약 중/판매 완료)를 본다.
- 구매자와 채팅으로 장소·시간을 정한다.

### 3.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 거래 상대의 마지막 응답 시각을 숨긴다. 개선: LUMA는 채팅 행에 마지막 메시지 시각과 **미응답** 상태를 표시한다(구매자 3/14 20:30 "어디세요?" 미응답).
- 레퍼런스는 판매 글의 가격 변동·수정 이력을 숨긴다. 개선: LUMA는 글 정보(i)에 "수정됨" 여부를 표시한다. 캐논에 수정 이력이 있으면 그대로, 없으면 표시하지 않는다.
- 레퍼런스는 판매 완료 글을 흐리게만 처리한다. 개선: LUMA는 상태 배지를 명시한다("판매 완료 3/11", "판매 완료 3/12", "예약 중").

## 6. 확인 사항

- **Q-OPEN:** 누리은행 간편비밀번호 오답 처리(횟수 제한·대기)가 캐논에 없다. 다른 자물쇠(기기 잠금 070921은 오답 6회째부터 30초, 메모 암호는 잠금 없음)와 다른 규칙을 만들지 않도록 **오답 잠금 없음**으로 확정할지 확인이 필요하다.
- **Q-OPEN:** [FEATURE_SPECIFICATION](../01-product/FEATURE_SPECIFICATION.md) 거래내역은 묶음(E-80~84)으로만 서술되고 개별 거래의 정확한 날짜·시각·상대가 일부만 있다. 화면에 표시할 개별 행을 새로 만들 때 캐논 수치를 넘지 않는 범위(합계·명시된 시각만)로 제한할지 확인이 필요하다.
- **Q-OPEN:** 한끼 재주문 확정 후 도현 반응(EV-27)과 F-MOVED 판정은 [PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 4.1이 단일 출처다. 재주문 확인 시트에 "문 앞에 두고 노크하지 마세요"를 그대로 노출할지, 배송지·요청을 요약할지 확인이 필요하다(추천: 그대로 노출).
- **Q-OPEN:** 지갑 결제 내역이 E-39의 일부인데 지갑 교통(승하차)과 결제(택시)를 서로 다른 문서가 나눠 가진다. E-39를 두 문서에서 중복 인용하는 것이 허용되는지, 혹은 대표 문서를 정할지 확인이 필요하다(추천: E-39는 MAPS 문서가 대표, COMMERCE는 결제 행만 교차 인용).
