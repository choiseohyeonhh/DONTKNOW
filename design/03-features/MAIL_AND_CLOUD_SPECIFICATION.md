# MAIL_AND_CLOUD_SPECIFICATION — 메일·찾기·시러스 ID 동기화

> **역할:** 메일 앱, 찾기 앱, 시러스 ID 동기화 화면의 기능·데이터·상태·상호작용을 구현 가능한 수준으로 정의한다. 정보가 기기·클라우드·서버 중 어디에 머무는지, 누가 같은 계정에 동시에 접속해 있는지가 이 게임의 "살아 있는 폰"을 만든다.
> **단일 출처:** 이 문서 = 메일·찾기·시러스 ID 동기화의 앱 기능·화면 데이터·상태. 정보 보존 위치와 동기화 물리 법칙(9 문서 1절)도 이 문서가 단일 출처다. 단서 원장은 [EVIDENCE_LEDGER.md](../01-product/EVIDENCE_LEDGER.md), 행동 증명은 [ACTION_PROOF.md](../01-product/ACTION_PROOF.md), 흔적은 [TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md), 사건·게이트·플래그는 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md), 계정·기기는 [CHARACTERS.md](../01-product/CHARACTERS.md).
> **참조:** [MAIL_AND_CLOUD_SPECIFICATION](MAIL_AND_CLOUD_SPECIFICATION.md) · [FEATURE_SPECIFICATION](../01-product/FEATURE_SPECIFICATION.md) 6절·10절 · [SETTINGS_SPECIFICATION](SETTINGS_SPECIFICATION.md) 1~4절 · [PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 4.6·6.1·6.4 · [TRACES_AND_REACTIONS](../01-product/TRACES_AND_REACTIONS.md) · [BUSINESS_RULES](../01-product/BUSINESS_RULES.md) 4절 · [SYSTEM_SHELL_SPECIFICATION](SYSTEM_SHELL_SPECIFICATION.md).
> **화면:** 화면 ID 목록의 단일 출처는 [NAVIGATION_ARCHITECTURE.md](../02-design/NAVIGATION_ARCHITECTURE.md)이고, 레이아웃 수치는 [SCREEN_SPECIFICATIONS.md](../02-design/SCREEN_SPECIFICATIONS.md)가 단일 출처다. 이 문서의 `SCR-`는 제안이며 확정은 총괄이 한다.

## 1. 정보가 머무는 네 곳 (캐논)

| 위치 | 예 | 지울 수 있는 사람 | 플레이어가 보는 조건 |
|---|---|---|---|
| **기기에만** | 음성 메모 "새로운 녹음 37"(동기화 대기), 버스트 원본, 로컬 사진 편집 기록 | 기기를 쥔 사람 / 원격 지우기 | T1 |
| **클라우드 동기화** | 메모, 사진(숨김 앨범 포함), 톡, 메일, 루프 부계정 | 계정에 로그인한 누구든(도현의 슬레이트 포함) | T1(캐시) — 온라인이 되면 원격 변경이 반영됨 |
| **서버에서 대기** | 예약 메일(3/18 09:00), 블링크 미전송 읽음, 원격 지우기 명령 | 계정 소유자 / 플레이어(예약 메일은 폰에서 수정·취소 가능) | T2 |
| **남의 계정** | 하린·서아·강민석의 게시물 | 그 사람 | T2(공개분만) |

**LUMA 동기화 규칙(게임 세계의 물리 법칙):**

1. 큰 파일(음성 메모·동영상·버스트)은 **Wi-Fi에서만** 업로드된다. 3/14~3/15 폰은 셀룰러만 있었으므로 녹음은 올라가지 않았다.
2. 온라인이 되면 **서버 기준으로 맞춘다.** 다른 기기에서 지운 항목은 이 기기에서도 지워진다(최근 삭제로 가지 않는 영구 삭제 — 도현이 슬레이트에서 "최근 삭제"까지 비웠다).
3. 오프라인 중 이 기기에서 한 변경은 대기했다가 온라인 때 올라간다.
4. 알림 기록은 동기화 대상이 아니다(원본이 지워져도 알림 첫 줄은 남는다).
5. **다른 기기의 흔적도 들어온다.** 시러스는 Wi-Fi 암호·키보드 사전(텍스트 대치)·지도 최근 검색·웨이브 기록·날씨 지역·미리 알림·스크린 타임(기기 간 공유)을 기기끼리 맞춘다. 그래서 슬레이트에서 생긴 흔적이 온라인이 된 폰에 "다른 기기에서" 표시와 함께 보인다. 현실의 클라우드 계정과 같은 범위다.
6. **앱별 동기화 스위치**(설정 → 시러스 ID → 동기화): 끄면 그 앱은 원격 삭제가 닿지 않고, 새 데이터도 들어오지 않는다. 음성 메모는 꺼진 상태로 시작한다.

- 구현 원칙: "온라인/동기화/서버 대기"는 모두 클라이언트 안의 시뮬레이션이다. 실제 네트워크·서버·계정은 없다. 상태는 단일 상태 트리와 이벤트 로그로만 관리한다.

## 2. 메일 앱

### 2.1 계정과 폴더 (캐논)

- **시러스(dohyun.lee0921@cirrus.kr, A-01):** 학교·은행·경찰·택시·고시원·통신사·시러스 보안 알림.
- **mailbox.kr(dk.nowhere@mailbox.kr, A-02):** 굿잡, 블링크 가입, 루프 부계정 가입·재설정.
- 폴더: 받은편지함 / 보낸편지함 / 임시보관 / **나중에 보내기** / 보관 / 휴지통.
- 오프라인에선 3/15 03:58까지 받은 메일 캐시만. 온라인에서 이후 메일 수신.

### 2.2 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: Gmail, Apple Mail. 두 서비스 모두 (a) 계정 전환, (b) 폴더/라벨 목록, (c) 목록에서 보낸 사람·제목·미리보기·시각을 한 줄로 보여 주는 인박스, (d) 본문에서 첨부·머리글 확인, (e) 작성창의 받는 사람 자동 완성·첨부, (f) 예약 발송과 임시보관, (g) 검색을 핵심으로 둔다.

### 2.3 ② 참고할 기능과 사용자 행동

- 계정 전환으로 본 계정과 부 계정을 오간다.
- 받은편지함을 훑고, 한 메일을 열어 머리글(보낸 사람·받는 사람·시각)과 첨부를 확인한다.
- 첨부 파일을 파일 앱으로 저장하거나 다른 앱으로 공유한다.
- 답장·전체 답장·전달, 새 메일 작성, 임시보관.
- 예약 발송("나중에 보내기")을 열어 발송 시각·본문·첨부를 확인하고 수정·취소한다.
- 검색으로 보낸 사람·제목·본문을 찾는다.
- 메일을 길게 눌러 읽음/안 읽음, 보관, 휴지통 이동, 정보(i)를 연다.

### 2.4 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 계정·폴더·설정이 여러 깊이에 흩어져 "예약 메일이 어디 있는지"를 찾기 어렵다. 개선: 폴더 목록에서 **나중에 보내기**를 항상 최상위에 고정하고, 예약 메일이 있으면 폴더 행에 발송 예정 시각을 1건만 표시한다.
- 레퍼런스의 발송 취소는 짧은 시간창이 지나면 사라진다. 개선: LUMA는 예약 메일을 발송 전까지 **수정·지금 보내기·삭제** 세 동작을 한 화면에 노출한다. 단, 이 세 동작은 세계에 흔적으로 남는다(TR-09).
- 레퍼런스는 첨부의 출처·크기를 숨긴다. 개선: 첨부 행에서 길게 누르면 정보(i)로 **파일 이름·크기·출처**를 바로 본다(대용량 첨부의 전송 가능 여부 판단).
- 레퍼런스는 오프라인과 온라인의 차이를 설명하지 않는다. 개선: 오프라인에서 발송 버튼을 누르면 "온라인이 필요합니다" 한 줄과 함께 임시보관으로 남긴다. 실패한 것처럼 보이게 하지 않는다.

### 2.5 ④ 이 게임에 적용하는 방식

- 메일은 **T1에서 캐시를 읽고, T2에서 새 메일·예약 메일·발송이 열리는** 앱이다. 오프라인에서 읽은 메일은 읽음 상태가 대기하고, 온라인 때 서버 기준과 합쳐진다.
- 본 계정과 부 계정을 계정 전환 시트로 오간다. 계정 전환은 흔적을 만들지 않는다(같은 기기의 저장된 계정).
- 메일 상세에서 머리글은 접힌 상태로 두고, 펼치면 보낸 사람·받는 사람·시각·첨부를 본다. 정보(i)는 길게 누르기로 연다.
- 예약 메일(E-50)은 **나중에 보내기** 폴더에서만 보인다. 상세 화면에서 발송 예정 시각(3/18 09:00)과 첨부(캡처 12장)를 확인하고, 아래 세 동작을 제공한다.
  - **그대로 둔다:** 아무것도 하지 않는다. 09:00에 발송된 것으로 간주한다(F-MAIL=sent). **오프라인이어도 09:00에 발송된 것으로 보고 엔딩을 판정한다.**
  - **수정:** 본문 편집·첨부 추가. 저장하면 슬레이트에도 수정이 보인다(TR-09).
  - **지금 보내기:** 확인 시트 1회. 확정하면 즉시 발송된다(F-MAIL=sent-now).
  - **삭제:** 확인 시트 1회. 삭제하면 발송되지 않는다(F-MAIL=deleted).
- 새 메일 작성의 받는 사람 주소는 플레이어가 직접 입력하거나, 출석요구 메일(E-11)·클립보드(E-180)에서 복사해 붙여넣는다. 게임이 주소를 자동으로 채우지 않는다.
- 김태윤 경위에게 보낸 메일은 **3/18 08:10에 일괄 회신**된다([PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 4.6). 그 전에 보낸 첨부·이름·번호판·위치가 엔딩 플래그가 된다.
- 메일을 수정하면 도현의 반응(EV-18)이 발생한다. 반응 문장과 경계 변화는 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md)가 단일 출처다.

### 2.7 ⑥ 화면 목록과 인터랙션 요약

| 화면 ID(제안) | 이름 | 진입 경로 | 표시 방식 |
|---|---|---|---|
| `SCR-MAIL-INBOX` | 메일함 목록 | 홈 → 메일 / 폴더 선택 | push |
| `SCR-MAIL-DETAIL` | 메일 본문 | 메일함 목록 → 메일 행 | push |
| `SCR-MAIL-COMPOSE` | 새 메일 작성 | 메일함 목록 우하단 작성 / 상세 → 답장·전달 | modal |
| `SCR-MAIL-SCHEDULE` | 예약 메일 상세 | 폴더 → 나중에 보내기 → 메일 행 | push |
| `SCR-MAIL-SCHEDULE-EDIT` | 예약 메일 수정 | 예약 메일 상세 → 수정 | modal |
| `SCR-MAIL-ACCOUNTS` | 계정 전환 | 목록 상단 계정 이름 | sheet |
| `SCR-MAIL-SEARCH` | 메일 검색 | 목록 상단 검색 | push |

- 인터랙션:
  - 목록: 계정 이름을 누르면 계정 전환 시트. 폴더 목록은 시트가 아니라 목록 상단의 접이식 구역으로 둔다(깊이 2단계 유지).
  - 행: 탭 = 상세, 길게 누르기 = 읽음/안 읽음·보관·휴지통·정보(i).
  - 상세: 머리글 펼치기, 첨부 탭 = 파일 앱 미리보기 또는 공유 시트, 길게 누르기 = 정보(i)·공유.
  - 작성: 받는 사람·참조·제목·본문·첨부. 전송은 온라인에서만. 오프라인이면 임시보관.
  - 예약 메일 상세: 발송 예정 시각 고정 표시, 수정·지금 보내기·삭제. 삭제·지금 보내기는 확인 시트.
  - 검색: 보낸 사람·제목·본문 포함 검색. 결과는 메일함별 그룹.

### 2.8 ⑦ 데이터(항목 필드)와 상태

| 항목 | 필드 |
|---|---|
| 메일 | `id`(E-xx), `accountId`(A-01/A-02), `folder`, `from`, `to`, `subject`, `body`, `sentAt`, `receivedAt`, `attachments[]`, `read`, `layer`(T1/T2/장식), `originDevice`, `flags`(예약·보안·미끼 등) |
| 첨부 | `name`, `size`, `source`, `localPath`, `evidenceId` |
| 예약 메일 | `sendAt`, `status`(pending/edited/sent-now/sent/deleted), `bodyEditable`, `attachments[]` |
| 계정 | `address`, `displayName`, `provider`, `folders[]` |

- 상태:

## 3. 찾기 앱

### 3.1 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: Apple 나의 찾기, Google 내 기기 찾기. 핵심 UX는 (a) 같은 계정의 기기 목록, (b) 선택한 기기의 지도 위치와 마지막 확인 시각, (c) 소리 재생, (d) 분실 모드, (e) 기기 지우기, (f) 위치 공유 상태다.

### 3.2 ② 참고할 기능과 사용자 행동

- 기기 목록에서 기기를 고르고 지도에서 위치를 본다.
- "마지막 활동" 시각을 확인한다.
- 소리를 재생해 기기를 울린다.
- 분실 모드를 켠다.
- 기기를 원격으로 지운다.
- 가족과 위치를 공유하거나 요청한다.

### 3.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 기기 위치의 정밀도를 과신하게 만든다. 개선: LUMA는 반경과 "N분 전"을 함께 표시하고, 반경 안의 장소 이름을 지도 라벨로 보여 주되 **어느 장소인지 강조하지 않는다.** 정밀도 한계를 화면이 정직하게 말한다.
- 레퍼런스는 소리 재생·분실 모드·기기 지우기의 결과를 즉시 알려 주지 않는다. 개선: 실행 직후 "요청을 보냈습니다"만 표시하고, 상대의 반응은 메시지·상태로만 온다(흔적 원칙).
- 레퍼런스는 가족 위치 공유 요청의 상대 상태를 숨긴다. 개선: 요청 후 "수락 대기" 상태를 표시하되, 상대가 거절해도 알림을 띄우지 않는다.

### 3.4 ④ 이 게임에 적용하는 방식

- 온라인에서만 동작한다. 오프라인이면 기기 목록은 캐시(마지막 확인 시각)만 보이고 모든 버튼이 비활성이다.
- 기기: 도현의 폰(이 기기) / 도현의 슬레이트.
- 슬레이트는 **"성원구청역 일대 · 반경 300m · N분 전"**으로 보인다(E-73). 지도에 흐린 원. 원 안에 성원구청역, 청운고시원, 해담고시텔, 성원스파, 편의점, 교회가 라벨로 있다. 반경만으로는 셋 중 어디인지 모른다.
- 버튼: 소리 재생(EV-15) / 분실 모드 / 기기 지우기(플레이어가 슬레이트를 지울 수 있다 → F-WIPE-SLATE, 엔딩 D 조건).
- 소리 재생은 슬레이트를 울린다(TR-11). 반응은 DH 상태에 따라 다르다.
- 가족 위치 공유가 다시 켜지면(DH-4 이후, EV-33) 슬레이트가 **건물 단위**로 보인다.
- 플레이어의 폰이 온라인이면, 도현의 찾기에서도 이 폰이 "집"에 있는 게 보인다. 도현은 폰이 집에 있다는 걸 보고 "아빠?"라고 의심하기 시작한다([PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md)).
- **기기 지우기**는 확인 시트 2단계(대상 확인 → "되돌릴 수 없습니다"). 확정하면 슬레이트가 지워지고 도현과의 연락이 끊긴다. 되돌릴 수 없다.

### 3.5 ⑤ 다른 앱·게임 시스템과의 연결

> 이 절은 설정 앱의 시러스 ID → 동기화 화면에 들어가는 데이터·효과를 정의한다. 메뉴 트리·검색·화면 ID는 [SETTINGS_SPECIFICATION.md](SETTINGS_SPECIFICATION.md)가 단일 출처다.

### 4.1 ① 레퍼런스 서비스의 핵심 UX

- 레퍼런스: Apple ID의 iCloud 앱별 스위치, Google 계정의 앱별 동기화. 핵심 UX는 (a) 계정 단위 목록, (b) 앱별 켜기/끄기, (c) 저장 공간 사용량, (d) 끄기 전 확인 대화상자("이 기기의 데이터를 유지할지 삭제할지"), (e) 기기 목록과 로그아웃이다.

### 4.2 ② 참고할 기능과 사용자 행동

- 앱별 스위치를 끄고 "이 폰에 사본 유지" 또는 "이 폰에서 삭제"를 고른다.
- 저장 공간에서 동기화되지 않은 항목을 확인한다.
- 기기 목록에서 다른 기기를 보고 제거한다.
- 암호·보안에서 암호를 바꾸고 다른 기기를 로그아웃한다.
- 가족 목록에서 위치 공유를 관리한다.

### 4.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 끄기의 **결과**를 즉시 보여 주지 않는다. 개선: 스위치를 끄면 그 자리에서 "이 앱의 원격 삭제가 닿지 않습니다 / 대신 다른 기기의 새 데이터도 들어오지 않습니다" 두 줄을 표시한다.
- 레퍼런스는 오프라인에서 바꾼 설정이 언제 적용되는지 모호하다. 개선: 오프라인 변경은 "온라인 연결 시 적용" 배지를 행에 표시한다.
- 레퍼런스는 앱별 동기화와 기기 전체 지우기의 관계를 설명하지 않는다. 개선: 동기화 화면 하단에 "기기 전체 지우기는 동기화와 무관합니다"를 고정 문구로 둔다.

### 4.4 ④ 이 게임에 적용하는 방식

- 스위치는 **원격 삭제 방어**와 **다른 기기 데이터 수신**의 두 얼굴을 가진다. 끄면 원격 삭제가 닿지 않지만 도현의 실시간 데이터도 못 본다.
- 오프라인에서 끄면 첫 온라인 전에 적용된다 → 첫 온라인 때 지울 대상이 이미 이 폰에만 있다. 가장 영리한 방어. 대가: 그 앱에서 도현이 실시간으로 남기는 것(미리 알림 체크, 새 메모)을 못 본다.
- 동기화를 끈다고 상대에게 알림이 가지는 않는다. 도현은 "지웠는데 저쪽엔 남아 있는지" 알 수 없다.
- **음성 메모 스위치는 꺼진 상태로 시작한다.** 켜면 "새로운 녹음 37" 업로드가 시작되고(Wi-Fi, 게임 4분) 슬레이트에서 보인다(EV-14, TR-13).
- 메일 스위치는 끌 수 없다("메일 계정은 메일 앱에서 관리"). 예약 메일은 다른 방법으로 다룬다.
- 원격 지우기(EV-08)는 동기화와 무관하게 기기 전체를 지운다.

### 4.5 ⑤ 다른 앱·게임 시스템과의 연결

| 연결 | 내용 | 근거 ID |
|---|---|---|
| 원격 삭제 | 메모·사진·미리 알림 스위치가 EV-04/05/07의 방어 | E-204, EV-04, EV-05, EV-07 |
| 녹음 보존 | 음성 메모 스위치를 켜면 업로드·보존 | E-37, E-196, V-14, EV-14, TR-13 |
| 실시간 데이터 | 미리 알림·메모·스크린 타임·지도·웨이브·날씨 수신 | E-194, E-198, E-213, E-214, E-219, E-220 |
| 계정 보안 | 암호 변경·기기 제거는 DH-X | TR-15, EV-08 |
| 기기 목록 | 슬레이트의 존재·마지막 활동 | E-76 |

### 4.6 ⑥ 화면 목록과 인터랙션 요약

- 화면 ID는 [SETTINGS_SPECIFICATION.md](SETTINGS_SPECIFICATION.md)의 `SCR-SET-CIRRUS-SYNC`를 쓴다. 이 문서는 중복 ID를 제안하지 않는다.
- 인터랙션:
  - 행: 앱 이름 + 스위치 + 현재 상태(켜짐/꺼짐). 스위치를 끄면 확인 시트("이 폰에 사본 유지 / 이 폰에서 삭제"). 메일 행은 스위치 대신 "메일 앱에서 관리" 링크.
  - 행 하단: "다른 기기에서 추가됨" 배지가 붙은 데이터가 있으면 앱 이름 옆에 점.
  - 하단 고정: "기기 전체 지우기는 동기화와 무관합니다."
  - 오프라인: 스위치는 조작 가능. 변경 사항에 "온라인 연결 시 적용" 배지.

### 4.7 ⑦ 데이터(항목 필드)와 상태

| 항목 | 필드 |
|---|---|
| 동기화 앱 | `appKey`(photos/memos/reminders/mail/talkBackup/voiceMemos/keyboardDict/mapsWaveWeather/screenTime), `enabled`, `startState`, `pendingOffline`, `effectOnOff` |
| 저장 공간 | `appKey`, `usedBytes`, `synced`, `unsyncedItems[]` |

- 상태:
  - 로딩: 계정 확인 중.
  - 빈 화면: 해당 없음(항상 9개 행).
  - 오프라인: 변경 대기 배지.
  - 삭제됨: 해당 없음.
  - 잠김: 메일 스위치 비활성(끌 수 없음).

### 4.8 ⑧ 캐논 데이터 (원본 그대로)

**캐논 데이터 — 시러스 ID → 동기화 (E-204):**

| 앱 | 시작 상태 | 끄면 |
|---|---|---|
| 사진 | 켜짐 | "이 폰에 사본 유지 / 이 폰에서 삭제" 선택. 유지 → 슬레이트의 원격 삭제가 닿지 않음. 대신 슬레이트에서 새로 생긴 사진도 안 들어옴, 내 스크린샷도 슬레이트에 안 감 |
| 메모 | 켜짐 | 같음. "아빠한테"·"남은 거"를 원격 삭제에서 지킬 수 있다(EV-04 전에 꺼야 함) |
| 미리 알림 | 켜짐 | 도현의 실시간 체크를 못 보게 됨 |
| 메일 | 켜짐 | 끌 수 없음("메일 계정은 메일 앱에서 관리") |
| 톡 백업 | 켜짐 | 영향 없음(톡은 앱 계정이 별도) |
| **음성 메모** | **꺼짐** | 켜면 "새로운 녹음 37" 업로드 시작(Wi-Fi, 게임 4분) → 슬레이트에서 보임(EV-14) |
| 키보드 사전 | 켜짐 | 텍스트 대치 동기화 중단 |
| 지도·웨이브·날씨 | 켜짐 | 다른 기기 기록 중단 |
| 스크린 타임(기기 간 공유) | 켜짐 | 슬레이트 사용 시간 안 보임 |

- **오프라인 상태에서 스위치를 끄면** 온라인이 되기 전에 적용된다 → 첫 온라인 때 지울 대상이 이미 이 폰에만 있다. 가장 영리한 방어. 대가: 그 앱에서 도현이 실시간으로 남기는 것(미리 알림 체크, 새 메모)을 못 본다.
- 동기화를 끈다고 상대에게 알림이 가지는 않는다(현실과 같다). 도현은 "지웠는데 저쪽엔 남아 있는지" 알 수 없다.
- 원격 지우기(EV-08)는 동기화와 무관하게 기기 전체를 지운다.

**이 문서 6번 규칙(캐논):** 앱별 동기화 스위치(설정 → 시러스 ID → 동기화): 끄면 그 앱은 원격 삭제가 닿지 않고, 새 데이터도 들어오지 않는다. 음성 메모는 꺼진 상태로 시작한다.

## 5. 원격 지우기 (EV-08)

### 5.1 캐논 명세 (이 문서)

- 도현은 첫 온라인 + 경고 메시지(EV-06) 후 게임 내 30분 안에 반응이 없으면 슬레이트에서 "기기 지우기"를 실행한다.
- 명령은 서버에 대기하고 폰이 온라인일 때 실행된다.
- 실행 연출: 화면이 흰색으로 바뀌며 "지우는 중…" 진행 막대 8초 → LUMA 초기 설정 화면("안녕하세요"). 폰은 거기서 **1분 머문 뒤 엔딩 판정**이다([PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 6.4). 그때까지 경찰에 보낸 것만 남는다.
- 막는 방법: [BUSINESS_RULES](../01-product/BUSINESS_RULES.md) 4.1 표. 실행 후엔 되돌릴 수 없다.
- **방어적 설계:** 원격 지우기는 반드시 사전 경고(EV-06 메시지)가 있다. 경고 없이 플레이어의 진행을 파괴하지 않는다.

### 5.2 게임 시스템 연결

- 발동: EV-08 = EV-06+30(T+66), DH < 2.
- 해법: 답장(DH-2) / 방 사진(V-04, DH-3) / 비행기 모드 유지 / 시러스 암호 변경(DH-X) / 아무것도 안 함(지우기 실행). 상세는 [BUSINESS_RULES.md](../01-product/BUSINESS_RULES.md)와 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md).
- 지우기 실행 후 F-WIPED=true, 폰은 초기 설정 화면. 엔딩 판정 순서에 들어간다.
- 연출 상태: 진행 막대 8초 동안 입력을 받지 않는다(일시정지 메뉴만 가능). 진행 막대는 되돌릴 수 없다.

## 8. 확인 사항

- **Q-OPEN:** E-16의 시각 표기가 "3/17 21:xx"로 원본에 남아 있다. 보안 알림은 플레이어 행동마다 생성되므로 고정 시각이 아니라 **게임 시각 기준 상대 표기**로 구현해야 한다. 표기 규칙을 확정해야 한다.
- **Q-OPEN:** 이 문서 2.2의 E-218은 "보낸편지함에 취소 요청 메일이 함께 보임"이라고만 되어 있다. 취소 요청 메일 자체의 시각·본문·ID가 없다. 새 단서 ID를 만들지 않고, E-218 상세에서 "요청 접수 3/15 09:31"만 보여 주는 것으로 확정할지 확인이 필요하다.
- **Q-OPEN:** 이 문서은 "30분 안에 반응이 없으면"이라고 쓰고, [PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md)는 EV-06+30에 EV-08을 둔다. 구현 기준은 EV-06 수신 후 게임 30분으로 통일한다. 문서 표현만 다르다.
