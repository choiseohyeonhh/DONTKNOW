# MESSAGING_SPECIFICATION — 전화·메시지·톡·연락처

> **역할:** 전화, 메시지(시스템 문자 + 슬레이트와의 대화), 톡, 연락처의 기능·데이터·상태·상호작용을 구현 가능한 수준으로 정의한다. 이 네 앱은 "폰을 쥔 사람이 누구인가"를 드러내는 가장 직접적인 층이다. 읽음, 부재중, 다중기기 동기화가 모두 흔적이 된다.
> **단일 출처:** 이 문서 = 전화·메시지·톡·연락처의 앱 기능·화면 데이터·상태·문구. 계정·기기·앎의 범위는 [CHARACTERS.md](../01-product/CHARACTERS.md), 행동 증명은 [ACTION_PROOF.md](../01-product/ACTION_PROOF.md), 흔적은 [TRACES_AND_REACTIONS.md](../01-product/TRACES_AND_REACTIONS.md), 사건·NPC 상태는 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md), 단서는 [EVIDENCE_LEDGER.md](../01-product/EVIDENCE_LEDGER.md).
> **참조:** [FEATURE_SPECIFICATION](../01-product/FEATURE_SPECIFICATION.md) 1~3·11절 · [SYSTEM_SHELL_SPECIFICATION](SYSTEM_SHELL_SPECIFICATION.md) 4·8·9절 · [BUSINESS_RULES](../01-product/BUSINESS_RULES.md) 6절 · [PROGRESSION_AND_ENDINGS](../01-product/PROGRESSION_AND_ENDINGS.md) 4.1~4.3 · [TRACES_AND_REACTIONS](../01-product/TRACES_AND_REACTIONS.md) · [SETTINGS_SPECIFICATION](SETTINGS_SPECIFICATION.md) 7절.
> **화면:** 화면 ID 목록의 단일 출처는 [NAVIGATION_ARCHITECTURE.md](../02-design/NAVIGATION_ARCHITECTURE.md), 레이아웃 수치는 [SCREEN_SPECIFICATIONS.md](../02-design/SCREEN_SPECIFICATIONS.md), 컴포넌트는 [COMPONENT_SPECIFICATIONS.md](../02-design/COMPONENT_SPECIFICATIONS.md), 토큰 이름은 [DESIGN_TOKENS.md](../02-design/DESIGN_TOKENS.md)를 따른다. 이 문서의 `SCR-`는 제안이며 확정은 총괄이 한다.

## 0. 범위와 접근 층

| 앱 | 영역 코드 | 접근 층 | 온라인 필요 | 계정·기기 |
|---|---|---|---|---|
| 전화 | `PHONE` | T1 | 아니오(기록) / 발신 불가 | D-01 도현의 폰. 회선 분실 정지 |
| 메시지 | `MSG` | T1(캐시) / T2(시러스 메시지) | 시러스 메시지 송수신 | A-01 시러스 ID |
| 톡 | `TALK` | T1(캐시) / T2(동기화) | 읽음 전송·송수신 | A-31 도현, 다중기기 |
| 연락처 | `CONT` | T1 | 아니오 | D-01 로컬 |

- **회선은 끝까지 "서비스 없음"이다.** 전화 발신과 셀룰러 문자 발신은 불가능하다. 메시지 앱의 시러스 메시지와 톡은 데이터 앱이므로 온라인에서만 동작한다.
- 문자·톡·메시지의 발신자는 상대가 도현으로 보인다. 플레이어가 정체를 밝히기 전까지 상대는 도현이 보낸 줄 안다([BUSINESS_RULES.md](../01-product/BUSINESS_RULES.md) 6절).
- 모든 온라인·동기화·서버는 클라이언트 안의 시뮬레이션이다. 실제 SMS·메신저·계정은 없다.

## 1. 전화

### 1.1 ① 레퍼런스 서비스의 핵심 UX

레퍼런스: iOS 전화 앱, Android 다이얼러. 핵심은 (a) 최근 기록 목록(발신·수신·부재중, 상대 이름·번호·시각·통화 시간), (b) 키패드, (c) 연락처와의 분리, (d) 통화 상세에서 여러 번 걸기·문자 보내기, (e) 부재중 강조다.

### 1.2 ② 참고할 기능과 사용자 행동

- 최근 기록을 시간 역순으로 훑고, 부재중을 구분한다.
- 항목을 눌러 통화를 시도하거나 상세에서 시각·통화 시간을 확인한다.
- 키패드로 번호를 입력한다.
- 항목을 길게 눌러 정보(i)·복사를 연다.

### 1.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 발신 실패를 "통화 종료"처럼 보여 준다. 개선: LUMA는 회선이 없으므로 [통화]를 누르면 즉시 "서비스 없음" 시트를 띄우고, 기록에 새 통화를 남기지 않는다. 실패를 성공처럼 보이게 하지 않는다.
- 레퍼런스는 부재중의 맥락(누가 먼저, 몇 번)을 숨긴다. 개선: 같은 상대의 연속 부재중은 한 묶음으로 접되, 첫·마지막 시각을 함께 보여 준다.
- 레퍼런스는 통화 기록과 문자 기록을 섞어 보여 준다. 개선: 전화 앱은 통화만, 메시지는 메시지만 보여 준다. 앱 경계를 섞지 않는다.

### 1.4 ④ 이 게임에 적용하는 방식

- 탭: 최근 기록 / 키패드. 연락처는 별도 앱이다.
- 회선 없음 → 발신 불가. [통화]는 "서비스 없음"만 표시한다. 수신 전화도 오지 않는다.
- 최근 기록은 3/15 03:58까지의 로컬 기록이다. 온라인과 무관하게 보인다.
- 통화 항목 탭 = 상세(상대·방향·시각·통화 시간). 길게 누르기 = 정보(i)·복사. 상세에서 다시 걸기는 "서비스 없음".
- 3/11 10:30 누리은행 고객센터 14분 12초는 도현이 스스로 사기 의심 신고를 한 근거다(E-31). 플레이어가 이 기록을 열어야 보인다.
- 3/14 18:41 아빠 부재중은 아버지가 마지막으로 아들에게 건 전화다. 3/14 21:30~23:58 지훈·서아·아빠 부재중 다수는 사건 이후의 수색 전화다.
- 발신 시도는 흔적을 만들지 않는다(회선이 없으므로 상대에게 가지 않는다).

### 1.5 ⑤ 다른 앱·게임 시스템과의 연결

| 연결 | 내용 | 근거 ID |
|---|---|---|
| 자수 계획 | 은행 고객센터 14분 통화가 "도현이 먼저 멈췄다"의 근거 | E-31, V-03 |
| 3/14 밤 | 아빠·지훈·서아의 부재중이 사건 시각과 겹친다 | E-01, E-12 |
| 흔적 | 발신 불가이므로 전화는 흔적을 만들지 않는다 | — |
| 대화 | 통화가 필요한 순간에도 실제 대화는 톡·메시지·DM으로 한다 | [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md) 4.2 |

### 1.6 ⑥ 화면 목록과 인터랙션 요약

| 화면 ID(제안) | 이름 | 진입 경로 | 표시 방식 |
|---|---|---|---|
| `SCR-PHONE-RECENTS` | 최근 기록 | 홈 독 → 전화 | push |
| `SCR-PHONE-KEYPAD` | 키패드 | 전화 → 키패드 탭 | push |
| `SCR-PHONE-CALL-DETAIL` | 통화 상세 | 최근 기록 → 항목 | push |

- 최근 기록: 방향 아이콘 + 이름/번호 + 시각 + 통화 시간. 부재중은 라벨로 구분하고 색만으로 표시하지 않는다.
- 키패드: 숫자 입력, 길게 눌러 0 = +. [통화] = "서비스 없음" 시트.
- 상세: 상대·방향·시작 시각·통화 시간·정보(i). [통화] 비활성.

### 1.7 ⑦ 데이터(항목 필드)와 상태

| 항목 | 필드 |
|---|---|
| 통화 기록 | `id`, `direction`(in/out/missed), `counterpartName`, `number`, `startAt`, `durationSec`, `device`(D-01), `evidenceId` |
| 연락처 연결 | `contactId`(CONT) |
| 상태 | `service`(none), `callAttempt` |

- 상태:
  - 로딩: 없음. 로컬 기록이라 즉시 표시한다.
  - 빈 화면: 기록 없음. "최근 통화가 없습니다"만 표시한다.
  - 오프라인: 기록은 로컬이라 그대로 보인다. 발신은 원래 불가.
  - 삭제됨: 해당 없음. 플레이어가 통화 기록을 지우는 기능은 없다.
  - 잠김: T0에는 전화 앱에 들어갈 수 없다(잠금화면 [통화]만 실패).

### 1.8 ⑧ 캐논 데이터 (원본 그대로)

- 탭: 최근 기록 / 키패드(연락처는 별도 앱). 회선 없음 → 발신 불가("서비스 없음").
- 최근 기록(3/15 03:58까지): 3/11 10:30 누리은행 고객센터 1588-XXXX 발신 14분 12초(E-31), 3/14 18:41 아빠 부재중, 3/14 21:30~23:58 지훈·서아·아빠 부재중 다수.

## 2. 메시지

### 2.1 ① 레퍼런스 서비스의 핵심 UX

레퍼런스: iOS 메시지, Android 메시지. 핵심은 (a) 대화 목록(상대·마지막 메시지·시각·안 읽음), (b) 말풍선 대화, (c) 발신자 이름이 없는 단축번호(은행·경찰·통신사) 처리, (d) 읽음 표시, (e) 사진·파일 첨부, (f) 정보(i)에서 보낸 사람·시각 확인이다.

### 2.2 ② 참고할 기능과 사용자 행동

- 대화 목록에서 시스템 문자와 개인 대화를 구분해 본다.
- 대화를 열어 말풍선을 읽고, 답장·복사·공유·정보(i)를 연다.
- 첨부를 열거나 저장한다.
- 읽음 시각과 보낸 기기를 확인한다.

### 2.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 은행·경찰·통신사 단축번호를 같은 목록에 섞어 중요한 개인 대화를 묻는다. 개선: LUMA는 발신자 유형을 라벨로 표시하고, 시스템 문자는 앱 이름·기관명을 제목으로 쓴다.
- 레퍼런스는 메시지의 "보낸 기기"를 보여 주지 않는다. 개선: 정보(i)에 **보낸 기기**를 넣는다. 이 게임에서는 같은 계정의 다른 기기가 핵심이다.
- 레퍼런스는 오프라인 발신 실패를 재시도로만 처리한다. 개선: LUMA는 "온라인이 필요합니다"와 초안 보존을 명시한다.

### 2.4 ④ 이 게임에 적용하는 방식

- 메시지 앱은 두 종류를 한 목록에 둔다.
  1. **시스템 문자:** 누리은행(3/12 지급정지 E-03), 성원경찰서(3/13 출석요구 E-04), 온통신(3/15 분실 정지), 한결캐피탈 1600-XXXX "입금 확인" 19건(E-05).
  2. **슬레이트와의 대화:** 도현이 시러스 메시지로 폰에 말을 건다(EV-06). 발신자 "dohyun.lee0921@cirrus.kr" — 자기 자신의 계정 주소다. 정보(i) "보낸 기기: 도현의 슬레이트".
- 플레이어의 답장도 시러스 메시지다(온라인). 읽음 표시가 양쪽에 있어 도현이 언제 읽는지 보인다.
- 시스템 문자는 3/15 03:58 이전 캐시다. 온라인 후 새 시스템 문자가 추가되지는 않는다(회선 정지). 한결캐피탈 19건은 과거 기록이다.
- 슬레이트 대화는 온라인에서만 열리고 갱신된다. 오프라인에서는 3/15 03:58까지의 캐시만 보인다.
- 첫 온라인 후 게임 36분에 도현의 경고(EV-06)가 온다: **"이 폰 가지고 있는 사람. 30분 안에 대답 없으면 원격으로 지웁니다."** 화면에 타이머는 없다. 수신 시각과 상태바 시계로 플레이어가 계산한다.
- 답장 경로: 어떤 말이든 답장 → DH-2. "아빠다" 계열 → "아빠면 지금 내 방 사진 찍어 보내. 책상 서랍 열고." → 카메라 서랍 사진 전송(V-04) → DH-3. 자세한 상태 변화는 [PROGRESSION_AND_ENDINGS.md](../01-product/PROGRESSION_AND_ENDINGS.md) 4.1.
- 도현은 DH-4에서 "여기 와이파이 느려서 사진 못 보내"라고 한다(E-91). 위치를 직접 말하지 않는다.
- 메시지 앱에서 아빠·지훈·서아에게 보내는 것은 톡이 아니라 시러스 메시지다. 혼동하지 않도록 메시지 앱의 대화는 "시러스" 라벨을 붙인다.

### 2.6 ⑥ 화면 목록과 인터랙션 요약

| 화면 ID(제안) | 이름 | 진입 경로 | 표시 방식 |
|---|---|---|---|
| `SCR-MSG-LIST` | 대화 목록 | 홈 독 → 메시지 | push |
| `SCR-MSG-ROOM` | 메시지 대화 | 목록 → 대화 | push |

- 목록: 시스템 문자 / 시러스. 발신자 유형 라벨, 마지막 메시지, 시각, 안 읽음 표시. 고정 상단에 "시러스" 대화를 두지 않는다(시간순).
- 대화: 말풍선, 날짜 구분선, 읽음 표시. 길게 누르기 = 복사·공유·정보(i). 첨부 = 사진·파일.
- 시러스 대화 상단에 "도현의 슬레이트"와 계정 주소를 표시한다. 정보(i)에서 보낸 기기를 확인한다.
- 발신 실패: "전송 실패" + 재시도. 오프라인이면 입력은 남고 전송 버튼만 비활성.

### 2.7 ⑦ 데이터(항목 필드)와 상태

| 항목 | 필드 |
|---|---|
| 대화 | `id`, `type`(system/cirrus), `senderLabel`, `senderAddress`, `unread`, `lastMessageAt`, `evidenceIds[]` |
| 메시지 | `id`, `threadId`, `direction`, `body`, `sentAt`, `readAt`, `readByOther`, `originDevice`(D-01/D-02), `attachments[]`, `evidenceId` |
| 첨부 | `type`, `name`, `size`, `localPath`, `evidenceId` |
| 상태 | `onlineRequired`, `sending`, `failed` |

- 상태:

## 3. 톡

### 3.1 ① 레퍼런스 서비스의 핵심 UX

레퍼런스: 카카오톡. 핵심 UX는 (a) 하단 탭 `친구 / 채팅 / 더보기`, (b) 채팅 목록의 안 읽은 수 배지·마지막 메시지·시각, (c) 1:1·그룹방, (d) 내 말풍선 오른쪽·상대 왼쪽, 연속 메시지 묶음과 프로필 생략, (e) 안 읽은 사람 수 "1", (f) 날짜 구분선, (g) 길게 누르기 → 답장/복사/공유/정보(i), (h) 사진·파일 공유, (i) 대화방 서랍(사진·동영상 / 파일 / 링크), (j) 방 안 검색, (k) 대화방 설정(알림 끄기·방 이름), (l) 친구 탭 = 내 프로필 + 친구 목록 + 생일인 친구다.

### 3.2 ② 참고할 기능과 사용자 행동

- 친구 목록에서 상대를 찾아 1:1 대화를 연다.
- 채팅 목록에서 안 읽은 방을 확인하고 연다.
- 말풍선을 길게 눌러 답장·복사·공유·정보(i)를 쓴다.
- 사진·파일을 보내고, 대화방 서랍에서 모아 본다.
- 방 안 검색으로 지난 대화를 찾는다.
- 방 알림을 끄거나 방 이름을 바꾼다.
- 음성통화를 건다.

### 3.3 ③ 레퍼런스의 불편한 점과 개선

- 레퍼런스는 안 읽은 수와 읽음 상태가 여러 사람에게 동시에 보여 부담을 만든다. 이 게임은 그 부담을 **흔적**으로 쓴다. 개선하지 않고 정확히 재현하되, 읽음 표시가 사라지는 시점을 화면에 명확히 보여 준다("1"이 사라짐).
- 레퍼런스는 설정이 깊고 방마다 다르다. 개선: 대화방 설정은 알림 끄기·방 이름 두 항목만 둔다. 부가 탭(오픈채팅·쇼핑)은 없다.
- 레퍼런스는 오프라인에서 읽은 것이 나중에 어떻게 전송되는지 설명하지 않는다. 개선: 오프라인에서 읽으면 "읽음 대기"로 표시하고, 다음 온라인 때 전송된다는 것을 한 줄로 알려 준다.
- 레퍼런스의 친구 탭 생일 알림은 새 정보를 계속 만든다. LUMA는 연락처에 있는 생일만 쓰고, 3/17 당일 생일인 친구가 없으면 "오늘 생일인 친구 없음"만 표시한다. 새 인물·새 생일을 만들지 않는다.

### 3.4 ④ 이 게임에 적용하는 방식

- 레퍼런스는 생일·메모 같은 필드를 깊은 편집 화면에 숨긴다. 개선: LUMA는 상세 카드 첫 화면에 생일·회사·메모를 모두 보여 준다. 이 게임에서 생일은 열쇠다.
- 레퍼런스는 중복 연락처를 만들기 쉽다. 개선: 같은 번호는 한 카드로 합치고, 번호 없는 카드("K")도 주소 메모만으로 존재할 수 있게 한다.
- 레퍼런스는 검색에서 띄어쓰기·하이픈을 엄격히 다룬다. 개선: 표기 변형을 무시한다.

### 4.4 ④ 이 게임에 적용하는 방식

- 이름순 64명. 즐겨찾기: 지훈, 서아(2/14 이후 즐겨찾기 해제 표시 없음 — 그대로 둠).

## 5. 공통 대화 규칙

### 5.1 읽음·안 읽음

| 앱 | 표시 | 흔적 |
|---|---|---|
| 톡 1:1 | 안 읽은 사람 수 "1" | 온라인에서 열면 사라짐(TR-02) |
| 톡 그룹 | 안 읽은 사람 수 | 같은 규칙. 그룹 참여자 수는 캐논에 없으므로 표시하지 않는다 |
| 메시지(시러스) | 양쪽 읽음 시각 | 도현이 읽으면 보인다 |
| 루프 DM | "읽음" | TR-04 |
| 블링크 | 읽음 즉시 전송 | TR-06 |
| 메일 | 읽음 상태(보낸 사람에게 표시하지 않음) | 해당 없음 |

- 오프라인에서 읽은 것은 "읽음 대기"로 표시하고 다음 온라인 때 전송한다.
- 알림 미리보기로 본 것은 읽음이 아니다. 앱을 열어야 읽음이 간다.

### 5.2 다중기기·동기화

- 톡·메시지는 같은 계정의 슬레이트와 동기화된다. 슬레이트에서 보낸 메시지·읽음이 온라인 후 폰에 들어온다.
- 3/15 03:58 이전 캐시와 이후 동기화 데이터를 시각으로 구분한다. 새 데이터에는 "슬레이트에서" 표시를 붙인다(톡·메시지 모두).
- 원격 삭제 대상이 아니다. 계정 동기화 대상이다.

### 5.3 정체와 입력

- 정체를 밝히기 전까지 상대는 도현이 보낸 줄 안다. "아빠다"·"아저씨다"·"도현이 아빠입니다"를 보내야 바뀐다.
- 추천 문장은 상대별 고정 목록이고, 플레이어의 지식에 따라 바뀌지 않는다.
- 직접 입력은 [ACTION_PROOF.md](../01-product/ACTION_PROOF.md) 3절의 낱말만 알아듣는다. 정의되지 않은 문장은 인물별 기본 반응이다.
- 공유 첨부가 있으면 첨부의 단서 ID가 반응을 먼저 결정한다.

## 7. 확인 사항

- **Q-OPEN-111:** 톡 친구 탭의 "생일인 친구"는 3.4의 요구지만, 캐논에 3/17 당일 생일자가 없다. 이 문서는 "오늘 생일인 친구 없음"만 표시하고 새 인물·새 생일을 만들지 않았다. 다가오는 생일(아빠 4/3)을 여기에 노출할지 확인이 필요하다. 추천: 노출하지 않는다(연락처·캘린더에서 이미 얻는다).
- **Q-OPEN-112:** 단톡 "경영 26 새내기"의 글 시각은 EV-41의 3/17 22:30으로 통일한다. (해결 — Q-OPEN-008 결정)
- **Q-OPEN-113:** 단톡 "경영 26 새내기"의 참여자 수·참여자 이름이 캐논에 없다. 이 문서는 방 이름과 메시지만 표시하고 멤버 목록을 만들지 않았다. 멤버 목록이 필요한지, 필요하면 장식 인원으로 채울지 확인이 필요하다.
- **Q-OPEN-114:** 시스템 문자의 발신 번호는 누리은행·성원경찰서·온통신에 대해 확정되어 있지 않다. 이 문서는 기관명과 "1600-XXXX"(한결)만 표시한다. 실제 발신 번호를 표시할지 확인이 필요하다.
- **Q-OPEN-115:** 이 문서 2절은 메시지 앱에서 "슬레이트와의 대화"를 한 스레드로 두지만, 시러스 메시지와 시스템 문자를 같은 목록에 섞을지 별도 구역으로 나눌지 확정되어 있지 않다. 이 문서는 시간순 한 목록에 유형 라벨로 구분했다.
- **Q-OPEN-116:** 전화 앱의 최근 기록 중 "3/14 21:30~23:58 지훈·서아·아빠 부재중 다수"의 정확한 횟수·시각이 캐논에 없다. 이 문서는 한 묶음으로 표시하고 첫·마지막 시각만 보여 준다. 개별 항목을 만들지 않는다.
